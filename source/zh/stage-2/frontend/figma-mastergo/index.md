## 1. 为什么要学习前端设计工具？

在开始之前，我们需要回答一个简单的问题：为什么要学习前端设计工具？如果你已经能够用 HTML 和 CSS 构建页面，真的有必要再学习一个工具吗？

实际上，“让页面能够运行”和“设计一个好的产品”是两码事。代码关注的是内容在浏览器中的呈现方式以及跨设备的行为表现，而设计工具关注信息的排列方式、交互的顺序以及视觉优先级的传达。在一个画布上，你可以在写代码之前对布局、信息层级和交互模式进行比较。

如果直接跳到实现阶段或者马上让 AI 生成完整的前端页面，用户体验往往会比较粗糙。认真设计的产品会仔细考虑舒适度、层级和在不同屏幕上的信息传达。更好的工作流程是先从用户的角度安排界面，然后再转换或生成代码。

从协作的角度来看，设计工具还可以降低协调成本。设计师、产品经理和开发人员不再需要从模糊的说明或抽象的代码中想象同一个界面。大家可以围绕可见、可注释、可迭代的画布讨论版本、需求变化和反馈。现代设计工具不再只是绘图软件，它们还能生成部分代码、管理设计系统和组件库，并自动化重复性工作，如对齐、注释、导出和样式变更。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image8.png)

### 1.1 前端设计工具的发展

前端设计工具是长期演进的结果。在 1990 年代，Photoshop 以本地位图编辑为主导。大约在 2010 年，Sketch 引入了以矢量为先、面向组件的工作流程。到 2016 年之后，Figma 将协作推向云端，将个人设计工作转变为实时团队协作。到 2025 年，AI 已成为这些工具的实用组成部分，从“从一句话生成草稿”到“将设计转成可运行的前端结构”。“设计即代码”和“人机共创”不再只是口号。

本章将重点介绍两款具有代表性的现代设计工具：Figma 和 MasterGo。它们都覆盖了现代 UI 和 UX 工作所需的核心能力，包括矢量编辑、组件系统、自动布局和开发交接。同时，它们也都加入了实用的 AI 功能，帮助将原型转化为可运行的界面，而不改变整体设计意图。

## 1.2 这些工具链是如何出现的

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image9.png)

在专门的界面工具出现之前，UI 设计主要由“通用”设计工具处理，例如 Photoshop。设计师在本地使用分层的 PSD 文件构建整个界面，然后将这些庞大的源文件交给前端工程师。为了准确重现设计，前端工程师需要手动完成三项繁琐但必要的工作。

第一项是 **资源切片**：从 PSD 文件中一个一个提取按钮、图标、Logo、背景及其他视觉元素，然后将它们导出为网页实际可以加载的 PNG 或 JPG 文件。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image10.png)

第二是**测量尺寸**：手动检查元素的宽度、高度以及间距，以确保每一处都与设计稿像素级匹配。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image11.png)

第三是**手动读取标注**：提取那些“不可见但必要”的设计参数，比如字体大小、字体粗细、行高、RGB 或 HEX 颜色、阴影等等。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image12.png)

只有在这之后，实际的前端实现才开始。无论使用的是纯 HTML/CSS/JS，还是 Vue 和 React 等框架，核心流程都是类似的。前端会根据设计的层级和语义，以容器为基础重建页面。容器是布局边界，用来组织子元素，但自身并不直接成为最终内容。顶栏、侧边栏、文章列表和页脚等结构模块依赖容器；在每个模块内部，更小的容器负责排列标题、描述、时间戳或缩略图等细节元素。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image13.png)

在现代前端框架中，这些结构模块通常实现为**组件**。组件是具有清晰边界的可复用界面单元。它既包括布局容器，也包括交互逻辑。任何重复的设计元素，比如统一的按钮样式或可复用的文章卡片，都可以抽象为组件，以便在不同页面中重复使用，同时保持布局和样式一致。

然后样式层恢复视觉效果。导出的图片素材变为 `<img>` 标签或背景图像。测量得到的尺寸变为 CSS 属性，如 `width`、`height`、`margin`、`padding` 和 `line-height`。排版、颜色、阴影、圆角以及悬停或激活状态变为 CSS、CSS Modules、CSS-in-JS 或 Tailwind 规则。至此，导出的素材和标注提供视觉参数，而组件和结构模块提供代码组织，使界面可维护且可复用。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image14.png)

但本地文件的工作流程效率低下。版本通过邮件或云盘发送，容易混淆旧稿和新稿，协作需要大量手动协调。

随着移动界面变得更加复杂、迭代速度加快，Photoshop 的“全能型”模式变得过于笨重。此时 Sketch 出现了。它专注于 UI 设计本身，引入了 Symbols，用于高度可复用的元素，如按钮和表单控件，并与 Zeplin 等工具配合，实现自动标注和样式片段。Sketch 将组件思维引入设计工作流。然而，它仍然是基于本地文件的桌面工具，因此实时协作从未成为原生功能。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image15.png)

Figma 真正改变了游戏规则。自 2016 年起，它在浏览器中统一了 UI 设计、原型制作、评论和版本历史，支持多用户光标、在线评论、时间线历史和可分享链接。

![](/zh-cn/stage-2/frontend/figma-mastergo/images/image16.png)

从那时起，界面设计不再分散在不同的机器上。它变成了一个实时更新的共享在线画布。一旦发生这种变化，通过自动化和 AI 模型，设计与前端代码的界限变得更容易模糊。

最初，插件只能半自动将组件和样式信息导出到代码片段中，如React或Vue骨架和CSS变量。后来，设计平台开始支持MCP（模型上下文协议），为语言模型提供了一种标准且受控的方式来访问设计文件、插件接口和项目元数据。这使得将设计导出为代码变得更加直接。

插件和MCP之后的下一步是原生设计到代码生成。如今，一些工具可以直接从设计生成项目骨架、组件层级、样式系统和真实代码。这让设计师和前端工程师无需手动传输细节，有更多时间专注于用户体验和功能迭代。

## 2.Figma基础知识

现在让我们从概念转向实践操作。由于时间有限，我们只会讲解Figma的核心交互模型。目标很简单：即使你从未使用过设计工具，也应该能够跟上并完成练习。如果你想要更完整的攻略，可以参考Figma官方的初学者文档：

https://help.figma.com/hc/en-us/sections/30880632542743-Figma-Design-for-beginners

你也可以看看Figma的网站建设示例：

https://help.figma.com/hc/en-us/sections/35895585621655-Figma-Sites-collection

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image17.png）

左侧是项目创建和资源管理。右上角区域你会看到几个常见的入口点。`Make` 让 AI 从一句话中生成粗略的界面草稿。`Design` 是主要工作区，用于构建应用和网页界面、组件及原型。`FigJam` 类似于团队白板，用于笔记、流程和早期讨论。`Buzz` 用于品牌规模的资产制作。`Site` 用于将设计发布为无障碍网站或文档页面。

乍一看，Figma看起来很复杂。但像这样的工具通过反复练习会变得熟悉。你不必害怕犯错，也不必第一次就把所有东西都做对。关键是开始玩弄它。

在本教程中，我们将重点介绍`Design`工作区。

### 2.1 创建新的设计文件

在主页或右上角，选择**Design**以创建新文件。你将输入一个空白画布。

该界面大致分为三个区域：

- 左侧显示页面和图层，方便你检查页面结构和元素层级。
- 中间区域是画布，用于查看和排列当前设计。
- 右侧是属性面板，用于更改形状、颜色和样式细节。
- 工具栏允许你在选择、形状、文本、注释和插件之间切换。选择工具后，你可以按 `Esc` 返回默认指针。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image18.png）

### 2.2 创建你的第一个框架

在放置元素之前，我们需要一个清晰的页面边界。在 Figma 中，这个边界由 Frame 处理。你可以选择 Frame 工具或点击 `F`，然后在画布上拖出一个矩形区域。

1. 使用工具栏中的框架工具或点击`F`。
2. 在画布上拖曳一个矩形，并在右侧面板中将其宽度设置为类似 `1440`，高度设置为 `900`。
3. 将图层列表中的框架重命名为类似 `My First Page` 或你的项目名称。

这个框架成为一个完整屏幕的容器。你的标题、文本、按钮和图片都应该存在其中，而不是自由漂浮在画布上。在框架内工作有助于后续的滚动、响应性、导出和原型制作。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image19.png）

### 2.3 在框架内添加文本和基本元素

现在我们有了容器，先放最基本的界面元素：标题、字幕、按钮和占位图像块。

1. 选择文本工具（`T`），点击框架内添加标题，如`My Portfolio`。在右侧面板中增加字体大小和粗细。
2. 在标题下方添加一行辅助文本。使用更小的字体大小和稍大的行高，使阅读更舒适。
3. 画出一个按钮：
   用矩形工具画出 `200 x 48` 周围的东西，给它明显的填充颜色，并加一些边框半径。
   ![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image20.png）
4. 在顶部添加按钮文字，如 `Get Started`，然后选择矩形和文本，并横向和纵向对齐。
5. 在按钮旁边或下方添加一个较大的浅灰色矩形作为占位图像区域。

此时，你已经有一个非常粗略但结构完整的主页草稿：标题、一段正文、一个按钮和一个主展示区域。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image21.png）

### 2.4 使用自动布局来组织元素

如果所有元素都手动放置，页面很快就会变得混乱。Figma最重要的概念之一是**自动布局**，它将一组元素变成基于规则的容器。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image22.png）

选择主标题、字幕和按钮，然后在右侧面板点击**添加自动布局**。

这些元素现在被包裹在一个容器里，你可以调整一些有用的属性：

- 元素是垂直排列还是水平排列
- 元素间距
- 内容块与容器边缘之间的填充物

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image23.png）

你也可以在按钮内使用自动布局。这样可以有一个按钮，随着文字变化，宽度会自动调整。

选择按钮背景和按钮文本，添加自动布局，并将它们变成按钮容器。然后将宽度和高度都设置为**拥抱内容**。完成后，文本保持居中，按钮宽度会随着文本增加或缩小。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image24.png）

### 2.5 将按钮变成可重复使用的组件

现在让我们了解另一个重要概念：组件。组件是设计用于反复使用的元素。按钮就是一个完美的例子。

从已经有自动布局的按钮开始：

1. 选择整个按钮容器。
2. 右键点击并选择**创建组件**。
   ![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image25.png）

按钮现在从一组普通图层升级为组件主。当你需要在其他地方使用相同按钮样式时，可以从资产面板拖出。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image26.png）

每个插入的按钮现在都是该主控的同步实例。如果你后来更改主控的颜色、角半径或间距，所有实例都会同步更新。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image27.png）

到目前为止，你已经理解了Figma的基本使用。你不需要第一天就掌握每一个函数。只需构建你的第一个简单页面，熟悉上述核心操作，然后逐步探索更多功能。

## 3.MasterGo 基础知识

一旦你理解了基本的Figma工作流程，MasterGo就更容易上手了。你可以把MasterGo看作是Figma的中国版对应产品，只是在产品行为上有一些不同。总体来说，它遵循非常相似的布局和交互模型：画布、图层树、属性面板、组件、样式、自动布局和多人协作。更多细节可以参考官方MasterGo教程：

https://mastergo.com/tutorials/12？全程高能，MasterGo 最完整实用教程，让你从零到精通！

### 3.1 创建新设计文件

1. **进入MasterGo工作区**
   1. 打开MasterGo网站并登录。
   2. 输入后，你会看到一个类似文件列表或项目列表的主页，管理你的设计文件。
      ![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image28.png）

2. **创建新文件**
   1. 点击右上角的 `+ Design File` 按钮，或选择导入如 Figma 文件等文件。
   2. 点击后，你将进入一个空白画布，这是MasterGo的设计工作区。

3. **了解主要接口区域**
   一旦你了解了Figma，MasterGo的感觉非常相似。主要方面有：

   ![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image29.png）
   1. 顶部工具栏：左侧为文件位置和名称，中间为共用工具按钮，右侧为在线协作者、共享、缩放和预览控制。
   2. 左侧面板：图层和资源，包括页面列表和当前页面的结构。
   3. 中央画布：框架、组件和图形实际放置和排列的工作空间。
   4. 右侧属性面板：用于检查和编辑所选对象的大小、位置、对齐、填充、笔画、边界半径等。如果没有选择任何内容，则显示画布级别的设置。

### 3.2 创建你的第一个框架

在放置内容之前，我们需要一个页面容器来定义接口的边界和大小。在 MasterGo 中，这通常被称为 Frame。

**脚步声**

1. **选择框架工具**
   1. 在工具栏中找到框架或美术板工具。
   2. 或者使用快捷键，通常是根据当前界面的 `F`。
2. **在画布上拖出一个矩形区域**
   1. 拖出后，你会看到选定的区域。
   2. 右侧属性面板将显示其宽度和高度。
   3. 将宽度改为类似 `1440`，高度改为 `900`。
3. **重命名框架**
   1. 在图层面板中找到框架。
   2. 双击该名称，并将其重命名为类似 `My First Page` 的名称。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image30.png）

### 3.3 在美术板上构建内容

有了容器后，你可以用我们在Figma中已经用过的这些想法来构建类似的页面。你甚至可以尝试直接把Figma美术板上的文本元素复制到MasterGo中。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image31.png）

值得注意的是，自动布局的行为略有不同。在MasterGo中，如果你想让按钮宽度随文本扩展或缩小，首先需要围绕矩形元素创建一个容器或组件，如下所示：

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image32.png）

创建容器后，将按钮背景和文本放入共享容器，然后从右侧面板启用自动布局。这样按钮宽度就能成功响应文本长度。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image33.png）

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image34.png）

### 3.4 AI生成页面

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image35.png）

MasterGo 的一个特别有趣的功能是 AI 页面生成。你可以输入一句话或提供参考图片，MasterGo 可以为你生成可编辑的组件和代码。你可以用中文或英文写提示。系统会根据你的请求返回一个结构清晰的页面草稿。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image36.png）

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image37.png）

设计文档生成后，点击开始生成，并短暂等待渲染结果：

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image38.png）

此时，你有两个选择：

- 点击蓝色按钮，将生成的结果直接插入画布中
- 打开代码预览，获取当前完整页面的代码

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image39.png）

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image40.png）

将结果放入画布后，你可以进一步细化整体布局和元素细节，如排版、颜色和间距，直到最终效果符合你的期望。

![]（/zh-cn/stage-2/frontend/figma-mastergo/images/image41.png）

**如何将这些设计草稿转化为真正能在浏览器中运行的前端代码？**

::: 提示 下一个教程
关于详细工作流程，请继续阅读[从设计原型到项目代码]（../design-to-code/）。你将学习：

- **直接多模态AI转换**：将你的设计截图发送给AI，直接生成HTML或React代码
