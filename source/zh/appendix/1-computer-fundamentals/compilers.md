## 0.大局：编译流程概述

想象一下，你是一个翻译家，负责将一部中国小说翻译成英文。你不会逐字逐句地翻译。相反，你会：

1. **识别单词** — 将句子拆分为单个单词（词汇分析）
2. **理解句法** — 判断句子结构是否正确（句法分析）
3. **理解语义** — 确保意义连贯且无矛盾（语义分析）
4. **打磨和精炼** — 使翻译更自然流畅（代码优化）
5. **输出翻译** — 编写最终英文版本（代码生成）

编译器做的事情完全一样，只不过它翻译的是编程语言。

## 1.编译器的六阶段流水线

编译器的工作可以分为六个阶段，就像工厂的装配线，每个阶段交接到下一个阶段。

<编译器演示 />

::: 提示 编译流程
1. **词汇分析**：将源代码拆解为词（词）
2. **语法分析**：将代币组织成语法树（AST）
3. **语义分析**：检查类型是否正确且变量是否声明
4. **中间码生成（IR生成）**：生成平台无关的中间表示
5. **代码优化**：使中间代码更高效
6. **代码生成**：生成目标平台的机器码
:::

| 阶段 | 输入 | 输出 | 类比 |
|------|------|------|------|
| 词法分析 | 源代码字符流 | 记号流 | 将句子拆分成单词 |
| 语法分析 | 记号流 | AST（语法树） | 分析句子结构 |
| 语义分析 | AST | 类型AST | 检查意义是否合理 |
| 中间代码 | 类型AST | IR | 编写初稿 |
| 代码优化 | IR | 优化后的IR | 打磨和精简 |
| 代码生成 | 优化后的IR | 机器码 | 输出最终版本 |

## 2. 词法分析：源代码的记号化

词法分析是编译的第一步。编译器从左到右扫描源代码的每个字符，将它们组合成有意义的**记号**。

<LexerTokenDemo />

就像你在阅读英文句子时，大脑会自动将字母组合成单词一样，词法分析器将字符组合成记号:

```
Source code: let x = 10 + 5;

Token stream:
[let]   → Keyword (language reserved word)
[x]     → Identifier (variable name)
[=]     → Operator (assignment)
[10]    → Numeric literal
[+]     → Operator (addition)
[5]     → Numeric literal
[;]     → Separator (statement end)
```

::: 提示 五种类型的标记
- **关键字**：语言保留的特殊单词，例如 `let`, `if`, `return`, `function`
- **标识符**：程序员定义的名称，例如变量名和函数名
- **字面量**：直接写在代码中的值，例如数字 `42` 和字符串 `"hello"`
- **运算符**：执行操作的符号，例如 `+`, `-`, `=`, `===`
- **分隔符**：用于分隔代码结构的符号，例如 `;`, `,`, `(`, `)`
:::

## 3. 语法分析：构建语法树 (AST)

词法分析将代码拆分为标记，但标记只是孤立的“单词”。语法分析的任务是根据语法规则将这些标记组织成**抽象语法树 (AST)**——它反映了代码的结构和运算符优先级。

```
Expression: 1 + 2 * 3

Syntax tree:        Why this way?
       +       Because * has higher
      / \      precedence than +,
     1   *     so 2 * 3 groups
        / \    together first
       2   3
```

::: 提示 AST 的重要性
AST 是编译器的“核心数据结构”。后续的语义分析、优化和代码生成都基于它。现代开发工具也大量使用 AST：
- **ESLint**：解析代码为AST，并检查规则违规
- **更漂亮**：解析为AST并重新格式化输出
- **Babel**：解析AST →转换→生成兼容代码
- **IDE 重构**：基于 AST 执行安全变量重命名和函数提取
:::

|语法结构 |令牌序列 |AST 节点 |
|---------|-----------|---------|
|变量声明 |`let` @1@@ @2@@ `10` |变量声明 →标识符字面 |
|函数调用 |`add` `(` @6@@ @7@@ `2` `)` |调用表达式→标识符参数 |
|条件语句 |`if` @11@@ `a` `>` @14@@ `)` |If语句→二进制表达式块 |

通过可视化，你会发现AST的核心模式其实相当简单：

|代码结构 |AST 根节点 |子节点 |

- **树摇动**：分析 AST 中的导入/导出以移除未使用的代码
:::

## 5.语义分析与代码优化

语法分析确保代码“结构正确”，但结构正确并不意味着“语义正确”。语义分析检查代码的含义是否有效，而代码优化则使程序运行更快。

<CompilationPracticeDemo />

### 5.1 语义分析与类型检查

|检查 |示例 |结果 |
|---------|------|------|
|类型检查 |`int x = "hello"` |类型不匹配 |
|作用域检查 |使用未声明变量 `y` |变量不存在 |
|类型推理 |`1 + 2.0` |推断结果为浮点数 |
|参数检查 |`add(1, 2, 3)` 但函数只接受两个参数 |参数计数不匹配 |

::: 提示 你看到的大多数错误都来自语义分析
- `TypeError: Cannot read properties of undefined` — 类型检查
- `ReferenceError: x is not defined` — 范围检查
- `Expected 2 arguments, but got 3` — 参数检查
:::

### 5.2 代码优化：中间表示的等价转换

在生成最终代码之前，编译器会对中间代码进行各种优化。这些优化对程序员来说是透明的，但能显著提升性能。

|优化技术 |之前 |之后 |原理 |
|---------|-------|-------|------|
|常数折叠 |`x = 10 + 5` |`x = 15` |在编译时计算结果 |
|死代码消除 |`if (false) { ... }` |完全移除 |永远不会执行的代码 |
|恒定传播 |`x = 15; y = x * 2` |`y = 30` |直接替换为已知值 |
|环路不变码运动 |在循环内反复计算 `len = arr.length` |在循环之外移动 |避免冗余计算 |

## 6.优化技术的实践：编译器如何让代码更快

上面我们提到了几个优化技术的名称。现在让我们更深入地探讨编译器到底是如何做到这一点的。下面的交互部分展示了五种最常见的编译器优化方式。你可以直观地比较优化前后的代码。

<CodeOptimizationDemo />

现代编译器和JIT引擎（如V8、GCC、LLVM）会自动应用数十项优化。作为开发者，你不需要手动完成这些优化，但理解它们会帮助你：

- **编写更容易优化的代码**：例如，使用`const`代替`let`，可以让编译器更容易应用常数折叠
- **理解性能差异**：为什么小函数比大函数快？因为编译器可以将它们内联化
- **避免“去优化”**：某些编码模式阻碍编译器优化，如`eval()`和`with`

|优化技术 |触发条件 |性能影响 |开发者能做什么 |
|---------|---------|---------|-------------|
|常数折叠 |表达式中的所有常量 |消除运行时计算 |更多使用cont声明 |
|废代码消除 |无法访问代码或未使用结果 |缩小代码大小 |及时清理未使用的代码 |
|循环不变代码运动 |循环内的不变计算 |减少冗余计算 |手动提取也是个好习惯 |
|功能内联 |频繁调用的小函数 |消除调用开销 |保持函数小且聚焦 |
|常数传播 |编译时已知的变量值 |消除整个计算链 |使用常数代替魔数 |

## 7.编译 vs 解释 vs JIT

编写代码后，有三种“翻译方法”可以运行。每种方法都有其优缺点，直接决定了语言的性能特性和用例。

<CompileVsInterpretDemo />

|维度 |编译 |解释 |JIT（即时） |
|------|-------|-------|------------|
|过程 |先完全编译为机器码，然后执行 |逐行翻译并执行 |先解释，然后编译热代码 |
|执行速度 |最快 |最慢 |中等（热代码接近编译速度） |
|启动速度 |慢（需要编译） |快速（直接运行） |中等（需要预热） |
|跨平台 |需要重新编译 |自然跨平台 |跨平台 |
|代表性语言 |C，Rust，Go |Python，Ruby |JavaScript（V8），Java |

::: 提示 为什么JavaScript这么快？
V8的JIT编译器监控哪些代码被频繁执行（热代码），并将其编译成高度优化的机器码。因此，尽管JavaScript是一种“解释型语言”，但它在V8中的性能可以接近编译语言。这也是使Node.js能够在服务器端使用的基础。
:::

## 摘要

编译原理不仅仅是编译器开发者的知识。理解编译过程有助于你更好地理解错误信息、选择合适的编程语言，并编写更高效的代码。

回顾本章的要点：

1. **编译器是一个翻译器**：将可读的人类代码转换为可由机器执行的指令
2. **六阶段流水线**：词法分析 → 语法分析 → 语义分析 → 中间代码 → 优化 → 代码生成
3. **词法分析分解标记**：将字符流拆分为有意义的单元，如关键字、标识符和运算符
4. **语法分析构建抽象语法树（AST）**：根据语法规则将标记组织成树状结构，反映运算符优先级
5. **语义分析确保正确性**：类型检查、作用域检查——你遇到的大多数错误都来自这里
6. **编译器自动优化**：常量折叠、死代码消除、函数内联等技术自动提高代码的运行速度
7. **三种执行模型**：编译型最快，解释型最灵活，JIT结合了两者的优点
