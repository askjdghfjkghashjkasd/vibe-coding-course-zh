## 0. 大局观：算法概览

想象你需要在字典中查找一个单词：

- **方法 1**：从第一页开始，一页页翻过去（线性查找）
- **方法 2**：先根据首字母定位，然后用二分查找（二分查找）

两种方法都能找到单词，但效率天壤之别。**算法只是解决问题的方法。**

<AlgorithmDemo />

**算法核心指标：**

| 指标 | 含义 | 重要性 |
|------|------|---------|
| **时间复杂度** | 随数据量增加，运行时间增长情况 | 预测大规模情景下的性能 |
| **空间复杂度** | 随数据量增加，占用内存增长情况 | 评估内存消耗 |
| **正确性** | 是否总能产生正确结果 | 算法的基本要求 |

::: tip 本表逐行解析
**时间复杂度**：用大 O 表示法描述。O(n) 表示数据量翻倍时间翻倍；O(n²) 表示数据量翻倍时间增加四倍。

**空间复杂度**：也用大 O 表示法描述。有些算法用空间换时间（如哈希表），有些算法用时间换空间（如压缩算法）。

**正确性**：算法必须对所有可能的输入都能产生正确结果。边界情况（空输入、极大输入）最容易出错。
:::

## 1. 二分查找：每次消去一半

### 1.1 二分查找的工作原理

::: tip 二分查找如何工作？
**前提条件**：数据必须有序

**过程**：
1. 找到中间元素
2. 如果中间元素等于目标值，找到！
3. 如果目标值小于中间元素，继续在左半部分查找
4. 如果目标值大于中间元素，继续在右半部分查找
5. 每次消去一半，直至找到或确认不存在

**时间复杂度**：O(log n)

**现实生活类比**：猜数字游戏。我心里想一个 1-100 的数，你每次猜中间的，我告诉你大了还是小了。最多 7 次就能猜到（因为 2⁷ = 128 > 100）。
:::

### 1.2 二分查找的时间复杂度分析

|数据量 |线性搜索 |二分搜索 |
|--------|---------|---------|
|100 |100次 |7次 |
|1000 |1000 次 |10 次 |
|1,000,000 |1,000,000 次 |20 次 |
|1,000,000,000 |1,000,000,000 次 |30 次 |

::: 提示 逐行指南 本表格
**第一列（数据量）**：搜索数据量。你可以看到数据量从1000增加到100亿（增长了1000万倍！）

**第二列（线性搜索）**：最“基础”的方法——从头开始逐一检查。搜索次数等于数据量;数据越大，所需搜索次数越多。

**第三列（二分搜索）**：智能方法——每次减半。搜索次数仅取决于数据量的对数。即使有10亿条，也只需30次搜索！

**对比结论**：当数据量达到100万时，线性搜索需要100万次比较，而二分搜索只需20次——相差5万倍！
:::

::: 提示 对数增长的力量
二分搜索的时间复杂度为 O（log n），这意味着：

- 10亿条：最多30次搜索
- 1万亿条：最多40次搜索

这就是对数增长的强大力量——当数据增加1000倍时，搜索次数只增加10倍。
:::

## 2.分类：将混乱转化为秩序

### 2.1 常见排序算法

|算法 |时间复杂度 |特性 |用例 |
|------|-----------|------|---------|
|**气泡排序**O（n²） |简单但慢 |教学，小数据集 |
|**选择排序** |O（n²） |简单但缓慢 |小数据集 |
|**插入排序** |O（n²） |快速处理接近排序的数据 |小数据集，接近排序 |
|**快速排序** |O（n log n） |实际中最快 |通用排序 |
|**合并排序** |O（n log n） |稳定排序 |需要稳定性的场景 |
|**堆排序** |O（n log n） |现场排序 |内存受限场景 |

::: 提示 逐行指南 本表格
**气泡排序**：最基本的排序算法，就像水底升起的气泡。简单易懂，但速度最慢。适合学习排序概念，不适合实际使用。

**选择排序**：每次选择最小元素并将其置于最前面。同样简单，但无论数据是否排序，它执行的比较次数相同。

**插入排序**：就像玩扑克时整理手牌。将每个元素插入已排序的部分。对于几乎排序的数据非常高效。

**快速排序**：现实开发中最常用的排序算法。平均最快，但最坏情况（已排序数据）降级至O（n²）。

**合并排序**：采用“分而治之”方法，始终为O（n log n），但需要额外空间。适用于需要稳定排序的场景。

**堆排序**：使用堆数据结构进行排序。原地排序（无需额外空间），但实际操作中通常比快速排序慢。
:::

### 2.2 快速排序的复杂性分析

::: 快速排序的提示
**核心理念**：分而治之

1. 选择一个“枢轴”元素
2. 将小于枢轴的元素放在左边，大于枢轴的元素放在右边
3. 递归地对左右部分进行排序
4. 合并结果

**为什么它很快？**
- 每次分区后，枢轴元素就在它的最终位置上
- 平均而言，每次分区会消除大约一半的元素
- 时间复杂度 O(n log n)

**现实生活类比**：整理书架。拿出一本书，把薄的书放在左边，厚的书放在右边。然后对每一边重复此过程。
:::

## 3. 递归：调用你自己

### 3.1 递归的本质

::: tip 什么是递归？
**递归**是一种编程技巧，其中一个函数调用它自身。

**两个关键元素**：
1. **基例**：递归何时停止？
2. **递归步骤**：如何将问题分解为更小的子问题？

**经典示例：阶乘**```js
function factorial(n) {
  if (n <= 1) return 1        // Base case
  return n * factorial(n - 1) // Recursive step
}
```

**现实生活中的比喻**：俄罗斯套娃。打开一个娃娃，里面是个更小的，直到你找到最小的那个，无法打开。
:::

### 3.2 递归与迭代

|特征 |递归 |循环迭代 |
|------|------|-------------|
|**代码简洁** |通常更简洁 |可能更复杂 |
|**内存消耗**更高（调用栈）|更低 |
|**性能**略慢（函数调用开销）|更快 |
|**用例**树遍历、分治算法 |简单重复任务 |

::: 提示 逐行指南 本表格
**代码简洁性**：递归通常只需几行来表达复杂逻辑（如遍历树结构），而循环可能需要更多变量和嵌套。

**内存消耗**：递归使用“调用栈”在每个层存储信息，就像堆叠板一样——每次递归调用都会添加一个板。环路没有这种开销。

**性能**：每个函数调用都有开销（参数传递、栈操作等），因此递归通常比循环慢。

**用例**：递归在处理本质递归结构（如文件树、DOM树）的问题上表现出色;循环在简单重复操作（如数组迭代）方面表现出色。
:::

::: 警告 递归的陷阱
**堆栈溢出**：当递归过深时，调用栈空间耗尽。

**解决方案**：
- 切换到迭代
- 使用尾递归优化（部分语言支持）
- 限制递归深度
:::

## 4.贪婪的算法：在每个步骤中选择最优者

### 4.1 贪婪的做法

::: 提示 什么是贪婪算法？
**贪婪算法**在每一步都做出局部最优选择，希望找到全局最优解。

**适用条件**：
1. **贪婪选择性质**：局部最优性导致全局最优性
2. **最优子结构**：问题的最优解包含子问题的最优解

**经典例子：硬币找零**
- 目标：用最少的硬币制造特定数量
- 贪婪策略：始终选择最大的硬币
- 结果：67元=50 10 5 1 1（5枚硬币）

**现实比喻**：爬山时，总是走最陡的路向上。虽然你可能到达最高峰，但通常能找到一个好位置。
:::

### 4.2 贪婪算法的局限性

::: 警告 贪婪并不总能找到最优方案
**反例：硬币换钱**

如果硬币面额是[1， 3， 4]，你需要做6：
- 贪婪：4 1 1 = 3枚硬币
- 最优：3 3 = 2枚硬币

贪婪的算法在这里失败了！

**教训**：贪婪算法简单高效，但并不总能产出最优解。你需要证明问题满足贪婪条件，才能使用贪婪算法。
:::

## 5.算法设计范式

| 范式 | 思想 | 典型算法 | 适用问题 |
|------|------|---------|---------|
| **分治法** | 将问题分解为更小的子问题 | 快速排序、归并排序 | 可分解问题 |
| **贪心算法** | 每一步选择最优方案 | 最小生成树、哈夫曼编码 | 具有贪心性质的问题 |
| **动态规划** | 记录子问题的解 | 背包问题、最短路径 | 具有重叠子问题的问题 |
| **回溯法** | 试错；遇到困难时回溯 | 八皇后、排列组合 | 搜索问题 |

::: tip 表格逐行指南
**分治法**: 将大问题拆分为小问题，分别解决后再合并。就像打扫房子 — 把客厅、卧室和厨房分开打扫，每个地方单独清理，整个房子就干净了。

**贪心算法**: 总是选择当前最优的选项，而不考虑长期后果。就像吃饭时先吃最喜欢的菜 — 可能不是最优的饮食策略，但速度快。

**动态规划**: 记住中间结果以避免重复计算。就像做笔记 — 下次遇到相同问题只需查笔记而不必重新推导答案。

**回溯法**: 遇到死路时返回并尝试另一条路径。就像走迷宫 — 一条路不通时，回到上一个路口尝试另一条路线。
:::

## 6. 总结：算法设计的核心思想

让我们用类比总结各种算法思想：

| 思想 | 类比 | 关键启示 |
|------|------|---------|
| **二分查找** | 猜数字游戏 | 每次排除一半 |
| **排序** | 整理书架 | 建立秩序 |
| **递归** | 俄罗斯套娃 | 大问题分小问题 |
| **贪心算法** | 选择登山路线 | 局部最优 |

::: tip 核心见解
**算法的本质是“效率”和“正确性”之间的平衡。**

- 好的算法可以将程序效率提高几个数量级
- 但是过度优化可能引入复杂性
- 先保证正确性，再追求效率

理解算法思维比记住具体算法更重要：
- 分治法: 将大问题拆分为小问题
- 贪心算法: 每一步选择最优方案
- 动态规划: 记录子问题的解
- 回溯法: 试错；遇到困难时回溯
:::
