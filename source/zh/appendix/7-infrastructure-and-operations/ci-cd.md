# 持续集成 / 持续部署 自动化简介

::: tip 🎯 核心问题
**你的代码在本地运行良好，但如何让全世界的人都能访问它？**
:::

## 1. “上线”需求的动机

想象一下，你在家做了一顿丰盛的晚餐，非常美味。但问题是，只有你的家人可以品尝。你的邻居、安全人员、陌生人——他们都无法尝试。

你会怎么做呢？你需要**把食物搬到餐厅**。这就是“上线”的作用——它将你写的代码从个人电脑移动到一个全天候运行的“公共电脑”。这样，任何有互联网的人都可以访问你的网站。

<DeploymentOverviewDemo />

上线涉及许多步骤。就像开餐厅不仅仅是提供食物——你还需要租用场地、装修、获得许可、招聘员工，等等。网页开发也一样。从代码到用户可以访问的网站，中间有很多步骤。你需要完成构建、部署、配置网络、确保安全等等。

下面，我将分解整个过程。每一步都会详细讲解。即使是完全没有经验的新手，也能理解。

## 2. 构建：将代码变成“可移植的构建产物”

### 2.1 需要构建的动机

初学者常常问：代码写好以后，为什么不能直接放到服务器上供用户访问？

要回答这个问题，首先要了解你的代码是什么格式的。你可能使用 Vue、React、Express 或 Koa 等框架。这些框架有一个共同特点：**它们并不是直接供浏览器或服务器使用的**。

例如，写 Vue 代码时，你不是使用 `<template>` 和 `<script setup>` 这样的标签吗？只有 Vue 能理解这种语法。浏览器完全无法理解它。浏览器只认识三种语言：HTML（网页结构）、CSS（网页样式）和 JavaScript（网页逻辑）。Vue 组件语法对浏览器来说就像乱码——完全无法理解。

所以在把代码放到服务器之前，有一件重要的事你必须做：**将它翻译成浏览器能理解的语言**。这个翻译过程就是“构建”。

### 2.2 构建实际做了什么

构建不仅仅是翻译。它还会进行许多优化，使网站运行更快、使用资源更少。具体来说，它做了以下事情：

**步骤 1：解决依赖**

写代码时，你会使用各种第三方库，比如 Vue、Vue Router、Axios、Vite 等。用户不可能每次都从 npm 下载这些库——那会太慢。构建工具会分析代码，找到所有依赖，并将它们“打包”在一起。

**步骤 2：编译和转换**

这是最关键的一步。它将 Vue 组件编译成 HTML 和 JavaScript。将 SASS/LESS 编译成 CSS。将 ES6 语法转换为更兼容的 ES5 代码。经过这一步后，代码从“开发者能看的格式”变成“机器能执行的格式”。

**步骤 3：压缩和混淆**

压缩会移除所有空格、换行和注释。它将变量名从英文单词改为单个字母。例如，`userName` 变成 `a`，`calculateTotalPrice` 变成 `b`。这大大减小了文件体积，使用户下载更快。混淆后的代码几乎无法被人类阅读，这也提供了一定的“代码保护”。

**步骤 4：代码拆分**

你可能已经写了10个页面，每个页面都有自己的代码。但用户可能只会访问一个页面。为什么他们要下载其他9个页面的代码呢？构建工具会将代码拆分成多个块。用户只下载他们访问的页面的代码。这就是“懒加载”，可以显著提升首次访问的速度。

**步骤5：生成哈希值**

这是一个很多人容易忽略的非常重要的步骤。构建完成后，文件名会变成类似 `app.abc123.js` 和 `vendor.def456.css` 的形式。末尾的那个字母数字组合叫做“哈希值”。

哈希值的作用是：当代码以任何方式更改时，哈希值也会改变。浏览器就会知道“这个文件已经更改，我需要重新下载它。”对于未更改的文件，浏览器会继续使用缓存，而不重新下载。这确保了用户始终看到最新的代码，同时充分利用缓存来提高速度。

<DeploymentBuildDemo />

### 2.3 构建运行方法

大多数现代前端项目已经配置好了构建工具。只需记住一个命令：

```bash
# If using npm
npm run build

# If using yarn
yarn build

# If using pnpm
pnpm build
```

运行后，在项目根目录中查找一个 `dist` 文件夹（有时称为 `build` 或 `.output`）。它包含所有构建好的文件。这些文件最终将上传到服务器。无需进一步修改——只需将它们拖到服务器即可。

### 2.4 构建输出包含什么

打开 dist 文件夹，你会看到主要有三类文件：

- **HTML 文件**：通常称为 `index.html`。这是入口文件——浏览器首先加载它。
- **JS 文件**：所有 JavaScript 代码。可能有一个或多个。
- **CSS 文件**：所有样式代码。可能内联在 HTML 中，也可能是单独的 CSS 文件。

对于更复杂的后端项目（如 Node.js），构建输出可能是可执行文件或 Docker 镜像。但原则相同：将代码转换为服务器可以直接运行的形式。

## 3. 服务器：寻找一个“从不关闭的房子” 

### 3.1 服务器到底是什么

许多人第一次听说“服务器”时会觉得它是某种神秘的高端设备。其实并不复杂。**服务器只是计算机**——一台永远不会关闭、始终连接互联网的计算机。

你可能会问：我家已经有电脑了，为什么还要额外花钱租服务器？

好问题。让我给你解释一下：

首先，你的家用电脑无法全天 24 小时开机。你需要外出、睡觉，有时它还会崩溃并重启。但服务器不同——它是专门为此目的建造的。它可以全年 365 天不间断运行。网站始终可访问。

其次，你的家庭网络也不够好。家庭宽带上传速度通常很慢。而且家庭宽带 IP 是动态的——今天是一个 IP，明天可能是另一个 IP。根本无法作为网站服务器使用。服务器使用高速数据中心网络，IP 固定，速度极快。

第三，你的家用电脑没有“公网 IP”。什么是公网 IP？它是全球唯一的地址。只有通过这个地址，别人才能在互联网上找到你的电脑。你的家用电脑 IP 通常只在家庭网络内有效。外部的人根本找不到你。服务器不同——它有固定公网 IP。全世界的人都可以通过这个 IP 找到它。

### 3.2 选择服务器的方法

选择服务器时，看三个主要指标：**CPU 核心数**、**内存大小** 和 **磁盘空间**。这三项指标越高，服务器性能越好，价格也越贵。

对于初学者，完全没有必要购买高配服务器。记住这个简单指南：

- **个人项目、学习和练习**：1 核心，2GB 内存即可。每月大约几十元。
- **小型商业项目**：2 核心，4GB 内存。可以应对数千到数万的日访问量。
- **中型项目**：4 核心，8GB 或更高。需要专业运维团队。

另一个需要考虑的因素是：**位置**。如果你的用户主要在中国，购买国内服务器（阿里云、腾讯云）访问速度更快。如果用户主要在海外，购买国外服务器（AWS、谷歌云、DigitalOcean）或香港服务器。速度快且无需 ICP 备案。

### 3.3 国内还是国外

这是一个非常重要的问题。很多人一开始没深思熟虑，后来常常出了麻烦。

**购买国内服务器**意味着更快的速度和更低的延迟。缺点是需要进行ICP备案（向相关政府部门提交网站信息以供审核）。这通常需要一周到一个月的时间。并且国内服务器相对较贵。

**购买国外服务器**意味着无需ICP备案。买了就可以直接使用。价格可能也更便宜。缺点是中国大陆用户访问可能会比较慢。香港或新加坡的数据中心在这方面要好得多。

推荐的是：对于个人项目和学习/演示网站，可以购买香港或海外服务器，避免ICP备案的麻烦。对于需要长期运营的合法商业项目，建议购买国内服务器并正确备案——从长远来看可以节省很多麻烦。

### 3.4 主要云服务提供商比较

| 提供商 | 最适合 | 功能 | 新用户价格 |
|--------|--------|------|------------|
| 阿里云 | 国内业务 | 市场份额最大，生态系统完善 | 第一年的价格从几十到一百多元不等 |
| 腾讯云 | 小程序、游戏 | 对小程序开发支持良好 | 首年优惠力度大 |
| 华为云 | 企业用户 | 政府及政务项目首选 | 相对较贵 |
| DigitalOcean | 开发者 | 简单易用，价格透明 | 从 4 美元/月起 |
| Vercel | 前端项目 | 零配置，推送即部署 | 免费套餐已足够 |

对于初学者，最推荐的选项是**阿里云**或**腾讯云**的学生/新用户折扣。通常每年只需几十元，性价比极高。如果你做的是纯前端项目并想保持简洁，也可以直接使用**Vercel**或**Netlify**。无需购买服务器——只需推送代码即可自动部署。

### 3.5 获得服务器后的操作

购买服务器后，你会收到一封包含以下重要信息的邮件：

- **IP 地址**：类似`123.45.67.89`的数字字符串。这是服务器在互联网中的地址。
- **登录用户名**：通常为`root`（管理员账户）。
- **登录密码**：初始密码或设置密码的链接。

有了这些信息，你就可以使用**SSH（安全外壳）**远程登录服务器并进行配置。SSH就像向服务器发送加密的远程控制命令，让你可以在自己电脑上操作远在远方的服务器。

登录命令如下所示：

```bash
ssh root@123.45.67.89
# Press Enter and you'll be prompted for the password. Enter the correct password and you're logged in.
```

成功登录后，你将进入服务器的命令行界面。它看起来类似于在你自己的计算机上打开终端窗口。你可以在这里安装软件、创建文件夹以及修改配置。所有操作就像在本地电脑上一样。

## 4. 部署：将代码搬入“房子”

### 4.1 部署概述

部署就像是租了一台服务器（房子），然后把你的代码（家具）搬进去，开门营业。

具体来说，部署包括以下步骤：

1. **将代码上传到服务器**：将本地计算机上的构建产物传输到服务器。
2. **安装依赖**：服务器可能没有项目所需的包，需要安装它们。
3. **配置环境变量**：如数据库密码和 API 密钥等敏感信息。
4. **启动服务**：让应用运行起来，并开始监听用户请求。

这四个步骤听起来很复杂，但实际上并不难。下面，我将详细讲解每个步骤。

<DeploymentServerDemo />

### 4.2 上传代码到服务器的方法

**方法 1：FTP/SFTP 上传**

这是最直观的方法，就像使用云存储一样——把文件拖到服务器上。你可以在电脑上下载一个免费的程序，叫 **FileZilla**。输入服务器的 IP、用户名和密码，就可以像管理本地文件一样管理服务器文件。

**方法 2：Git 拉取**

这是推荐的方法。首先，在 GitHub、GitLab 或 Gitee 上创建代码仓库。将代码推送到云端。然后在服务器上使用 `git clone` 命令把代码拉下来。

好处是：后续更新代码时，只需在服务器上运行 `git pull`，无需每次都手动上传。同时代码安全存储在云端——即使服务器重装也没有问题。

**方法 3：持续集成 / 持续部署 自动部署**

这是最专业的方法，也是我强烈推荐的方法。通过配置 持续集成 / 持续部署（持续集成/持续部署），你只需将代码推送到 GitHub。持续集成 / 持续部署 系统会自动完成整个过程：拉取代码 → 安装依赖 → 构建 → 部署。你甚至无需登录服务器，一切都自动完成。

### 4.3 具体部署步骤

我们用最简单的方法——手动 Git 部署，来演示整个过程：

**步骤 1：连接到服务器**

```bash
ssh root@123.45.67.89
```

**步骤 2：安装必要的软件**

对于 Node.js 项目，您首先需要安装 Node.js：

```bash
# Using Ubuntu system as an example
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt install -y nodejs
```

**第3步：拉取代码**

```bash
# Create a directory for the website
mkdir -p /var/www/my-website
cd /var/www/my-website

# Clone the code repository (need to create the repository on GitHub first)
git clone https://github.com/your-username/your-repo-name.git .
```

**步骤 4：安装依赖项并构建**

```bash
# Install project dependencies
npm install

# Build the project (generates the dist directory)
npm run build
```

**步骤 5：使用 PM2 启动服务**

为什么使用 PM2？它是一个进程管理工具，可以让网站在后台运行。即使服务器重启，它也能自动重新启动。

```bash
# Install PM2 globally
sudo npm install -g pm2

# Start the website (assuming the entry file is index.js)
pm2 start index.js

# Set up auto-start on boot
pm2 startup
pm2 save
```

**第6步：配置 Nginx 反向代理**

Node.js 应用程序通常运行在 3000 或 8080 端口。但用户访问的是 80 端口（HTTP 默认端口）。您需要让 Nginx 将来自 80 端口的请求转发到应用程序端口。

```bash
# Install Nginx
sudo apt install -y nginx

# Create an Nginx configuration file
sudo nano /etc/nginx/sites-available/my-website
```

在打开的编辑器中，写入以下配置：

```nginx
server {
    listen 80;
    server_name example.com www.example.com;

    # Static files (build output) returned directly
    location / {
        root /var/www/my-website/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # API requests forwarded to Node.js backend
    location /api/ {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

保存并退出后，启用此配置：

```bash
# Enable the configuration
sudo ln -s /etc/nginx/sites-available/my-website /etc/nginx/sites-enabled/

# Test the configuration for errors
sudo nginx -t

# Restart Nginx
sudo systemctl restart nginx
```

现在访问 `http://example.com`（记得先将域名指向此服务器的 IP），你应该能看到网站了！

## 5. 域名和 DNS：给你的网站起一个好名字

### 5.1 购买域名的动机

有了服务器 IP，为什么还需要买域名？

想一想。记住一串数字，比如 `123.45.67.89` ——难道不难吗？是不是很容易输错？但是记住像 `baidu.com` 或 `taobao.com` 这样的名字就容易多了，对吧？

域名是你网站的名字。它易记、专业，还能体现你的品牌形象。想象一下，你告诉别人“访问我的网站，IP 是 123.45.67.89” versus “访问 imcool.com” ——哪个听起来更正规？

<DeploymentDnsDemo />

### 5.2 DNS 概览

好了。现在你已经购买了一个域名，比如 `my-awesome-website.com`。但问题是：计算机只懂 IP 地址，不懂像“my-awesome-website.com”这样的自然语言。

这就是 DNS 的作用。DNS 代表“域名系统”。你可以把它想象成一个巨大的“电话簿”，专门负责将易记的域名翻译成计算机可以理解的 IP 地址。

当你在浏览器中输入 `my-awesome-website.com` 并按下回车时，幕后发生的事情如下：

1. 浏览器询问 DNS：“嘿，my-awesome-website.com 的 IP 地址是多少？”
2. DNS 查阅“电话簿”，告诉浏览器：“它的 IP 是 123.45.67.89”
3. 浏览器使用这个 IP 地址找到服务器并发送请求

整个过程通常只需几十毫秒。用户几乎不会察觉。

### 5.3 DNS 配置方法

DNS 配置通常可以在两个地方完成：

**方法 1：在域名注册商处配置**

在购买域名的地方配置 DNS 记录。最常见的记录类型是 **A 记录**：

- **记录类型**：A
- **主机记录**：通常是 `@`（代表域名本身，例如 my-awesome-website.com）或 `www`（代表 www.my-awesome-website.com）
- **记录值**：服务器 IP 地址，例如 `123.45.67.89`

**方法 2：使用第三方 DNS 服务**

许多专业人士不使用域名注册商自带的 DNS，而是使用专门的 DNS 提供商，如 Cloudflare、阿里云 DNSPod 或腾讯云 DNS。这些服务通常更稳定、解析速度更快，并且附带 CDN 和 DDoS 防护等增值功能。

### 5.4 DNS 传播需要多久

这是很多人关心的问题。答案是：**不固定。通常从几分钟到 24 小时不等。**

修改 DNS 后，全球所有 DNS 服务器都需要同步这一修改。这就像丢一块石头到海里——涟漪需要时间才能传到远处的海岸。有些 DNS 服务器更新很快，几分钟即可生效。其他的则比较慢，可能需要较长时间。

你可以使用以下命令检查 DNS 是否已传播：

```bash
# Windows
ping your-domain.com

# Mac/Linux
ping your-domain.com
```

如果 ping 成功并显示服务器的 IP，说明 DNS 已经传播。

## 6. HTTPS：在您的网站上安装“锁”

### 6.1 HTTP 与 HTTPS 的区别

您可能注意到，有些网站地址以 `http://` 开头，而有些以 `https://` 开头。那个“s”很重要——它代表“Secure（安全）”。

**HTTP（超文本传输协议）** 是用于传输网页的协议。可以把它想象成一辆运载数据的卡车。但这辆卡车是**透明的**——里面的所有内容对任何人都是可见的。用户在 HTTP 网站上输入的密码和个人信息可能在传输过程中被中途的任何人拦截。

**HTTPS（安全超文本传输协议）** 给这辆卡车加了一个**封闭容器**，并配有一把钥匙。只有发送方和接收方拥有这把钥匙。即使有人在中途拦截，也无法理解里面的内容。这就是加密传输。

<DeploymentHttpsDemo />

### 6.2 使用 HTTPS 的动机

第一个原因：**安全**。没有 HTTPS，用户在网站上输入的密码是以明文传输的。任何有一点技术能力的人都能截获它们。如今，谁敢使用没有 HTTPS 的网站呢？

第二个原因：**浏览器警告**。像 Chrome 和 Edge 这样的现代浏览器会对没有 HTTPS 的网站显示“不安全”警告。用户看到警告图标会立即离开，更不用说注册或付款了。

第三个原因：**SEO**。搜索引擎如 Google 和百度会优先收录 HTTPS 网站。您的 SEO 排名会更好。

### 6.3 获取 HTTPS 证书的方法

过去，HTTPS 证书价格昂贵，每年需花费数百甚至数千元。现在有一个名为 **Let's Encrypt** 的组织提供完全免费的 SSL/TLS 证书。此外，社区还有许多自动化工具帮助您安装和更新证书。

**方法一：使用 Certbot（推荐）**

Certbot 是一个自动申请并配置 Let's Encrypt 证书的工具，非常简单：

```bash
# Install Certbot
sudo apt install -y certbot python3-certbot-nginx

# One-click certificate application and Nginx configuration
sudo certbot --nginx -d example.com -d www.example.com
```

在流程中，你会被问到一些问题，比如你的电子邮件（用于证书到期提醒）。回答后，证书会自动配置。访问网站，你会在地址栏看到一个小锁图标。

证书有效期为90天，但Certbot会自动设置续期cron任务。你基本上不用担心这个。

**方法二：使用Cloudflare**

如果你使用Cloudflare的DNS服务，根本不需要配置HTTPS证书。Cloudflare会自动为你的域名提供HTTPS支持。它甚至会帮你处理90天的续费。

### 6.4 配置HTTPS后发生的变化

配置 HTTPS 后，用户访问从 `http://example.com` 变为 `https://example.com`。这一变化带来了一系列安全保障：

1. **加密传输**：用户与服务器之间的所有通信均为加密。
2. **身份验证**：证书可以证明“我确实是这个网站”，防止钓鱼网站。
3. **数据完整性**：它可以检测数据是否被篡改。

## 7.持续集成 / 持续部署：让机器人完成工作

### 7.1 持续集成 / 持续部署 概述

持续集成 / 持续部署 是两个术语的缩写：**C**持续的**I**ntegration 和 **C**continuuous **D**eployment。你可以把它看作是一个自动完成工作的机器人系统。

没有持续集成 / 持续部署，每次你想发布新功能时，流程大致如下：

1. 打开你的电脑，登录GitHub
2. 拉取最新的代码
3. 进行测试以检查是否有漏洞
4. 手动构建项目
5. 登录服务器
6. 拉取最新代码
7. 安装依赖
8. 建设项目
9. 重新启动服务

这9个步骤每次发布都需要手动完成。很烦人，对吧？而且很容易漏掉步骤，比如忘记运行测试或忘记重启服务。

使用持续集成 / 持续部署时，过程变为：

1. 将代码推送到GitHub
2. 喝点茶，等待
3. （机器人自动完成上述9个步骤）
4. 网站会自动更新

<部署CicdDemo />

这就是持续集成 / 持续部署的魅力：**只需推送代码，其他一切都会自动完成。**

### 7.2 持续集成 / 持续部署的工作原理

典型的持续集成 / 持续部署流程如下：

**第一步：代码推送**

你已经完成了一个新功能的开发。把代码推送到GitHub。

**步骤2：触发CI（持续集成）**

GitHub会检测到代码变动，并通知CI系统（GitHub Actions、GitLab CI等）开始工作。

**步骤3：安装依赖并测试**

CI系统启动虚拟机，并在虚拟机上：
- 安装项目所需的所有依赖
- 运行测试代码以确保无漏洞
- 构建项目以生成输出

如果测试失败，CI会发送邮件通知。部署停止。有问题的代码不会部署到生产环境。

**步骤4：CD（持续部署）执行**

所有测试通过后，配置间系统：
- 通过SSH连接服务器
- 拉取最新代码
- 安装依赖
- 构建项目
- 重启服务

整个过程可能只需几分钟。全自动完成。

### 7.3 配置 GitHub Actions 的方法

GitHub Actions 是 GitHub 内置的 持续集成 / 持续部署 功能。没有额外费用（免费套餐对个人项目来说就足够了）。而且配置非常简单。

在项目根目录中创建一个 `.github/workflows/deploy.yml` 文件，并编写以下配置：

```yaml
name: Deploy to Production

# Trigger condition: whenever code is pushed to the main branch
on:
  push:
    branches: [main]

# Job list
jobs:
  # Deploy job
  deploy:
    # What system to run on
    runs-on: ubuntu-latest

    # Specific steps
    steps:
      # 1. Check out code
      - name: Checkout code
        uses: actions/checkout@v3

      # 2. Set up Node.js environment
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'

      # 3. Install dependencies and build
      - name: Install and Build
        run: |
          npm ci
          npm run build

      # 4. Deploy to server
      - name: Deploy to Server
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /var/www/my-website
            git pull origin main
            npm install
            npm run build
            pm2 restart all
```

这个配置文件告诉 GitHub Actions：

- 当 main 分支有新代码时触发
- 在 Ubuntu 机器上执行任务
- 首先安装 Node.js 18
- 然后安装依赖并构建项目
- 最后通过 SSH 连接服务器并执行一系列部署命令

配置完成后，每次你 `git push origin main`，GitHub 都会自动开始部署。非常方便。

## 8. 监控和日志记录：成为你网站的“夜间守望者”

### 8.1 监控的动机

网站上线后，理论上应全天候 24 小时不间断运行。但是现实世界并不完美。服务器可能宕机。网络可能中断。代码可能有 bug。在真实的生产环境中，各种不可预见的情况都可能发生。

如果没有监控，你只能等用户打电话告诉你“网站打不开”。到那时，往往已经太晚了。用户可能已经离开。

有了监控，你可以：

- **早期发现问题**：CPU 使用率 90%？提前增加服务器。
- **快速定位问题**：网站变慢？查看监控找出瓶颈。
- **了解情况**：每天有多少访客，流量最高时间是什么时候。

<DeploymentMonitorDemo />

### 8.2 需要监控的指标

最重要的监控指标如下：

| 指标 | 正常范围 | 超出时的处理措施 |
|--------|-------------|----------------|
| CPU 使用率 | < 70% | 升级服务器或优化代码 |
| 内存使用率 | < 80% | 检查内存泄漏 |
| 磁盘使用率 | < 80% | 清理日志或不必要的文件 |
| 网站可用性 | 100% | 检查服务是否正常运行 |
| 响应时间 | < 2 秒 | 优化数据库查询或增加缓存 |
| 错误率 | < 1% | 查看错误日志定位问题 |

### 8.3 配置监控的方法

**最简单的方案：Uptime Robot**

在 uptimerobot.com 注册账号。添加你的网站 URL。它会自动每 5 分钟检查一次网站是否正常运行。如果网站宕机，会发送邮件通知你。免费版本可以监控 50 个网站——对个人项目已经绰绰有余。

**中级方案：阿里云/腾讯云监控**

如果你的服务器在阿里云或腾讯云，它们自带监控功能。只需配置阈值告警即可。

**专业方案：Prometheus + Grafana**

这两者是监控界的“瑞士军刀”。功能非常强大，可以监控任何你能想到的指标，并创建美观的可视化。但配置相对复杂，适合有经验的开发者。

### 8.4 日志：排查问题的方法

监控告诉你“网站有问题”。但是具体问题是什么，以及为什么发生——你需要通过 **日志** 来查明。

日志是程序的“日记”，记录程序运行过程中发生的所有事情：

- 哪个用户在什么时候访问了哪个页面
- 数据库查询耗时多久
- 是否有错误以及错误信息是什么

**基础日志使用方法**

在服务器上查看应用日志：

```bash
# View PM2 logs
pm2 logs

# View Nginx access logs
tail -f /var/log/nginx/access.log

# View Nginx error logs
tail -f /var/log/nginx/error.log
```

**高级对木解法**

对于更复杂的项目，建议使用专业的日志采集工具：

- **Loki**：免费开源。与普罗米修斯同一个团队。
- **ELK（Elasticsearch Logstash Kibana）：功能强大但配置复杂。
- **Sentry**：专门用于收集应用错误的工具。自动收集错误信息。

### 8.5 警报：即时发现问题的方法

监控会告诉你有问题。但如果你没有盯着监控仪表盘呢？这正是**警报*发挥作用的地方。

当监控系统检测到异常时，警报会自动通过短信、微信、DingTalk、电子邮件等方式通知你。你可以设置不同的警报级别：

- **紧急（网站完全宕机）**：短信电话。必须立即得知。
- **严重（错误率激增）**：DingTalk/微信消息。发现时处理。
- **正常（CPU稍高）**：邮件摘要。每天检查一次。

警报配置的核心原则是：**分级警报，不要烦死自己。** 如果每条小事都给你发短信，你很快就会关闭警报。

## 摘要

服务上线是一项系统化的工程工作。它涵盖从代码构建到服务器部署，从网络配置到安全保护，从监控和警报到日志分析的方方面面。对于初学者来说，没有必要一开始就追求完美。首先运行最小可行版本（MVP），然后逐步完善这个基础。

整个过程的关键点可以总结如下：

### 核心流程

1. **构建** → 使用 `npm run build` 将代码转换为浏览器能理解的 HTML/CSS/JS
2. **部署** → 将构建输出上传到服务器。配置 Nginx 反向代理。
3. **Domain** → 购买域名并将 DNS 解析配置为服务器 IP
4. **HTTPS** → 使用Let's Encrypt申请免费证书。保护数据传输安全。
5. **持续集成 / 持续部署** → 配置自动部署。代码在推送后自动上线。
6. **监控** →配置监控和警报。立即发现问题。

### 学习路径建议

- **第1天**：使用 Vercel/Netlify 部署静态网页。体验“代码变成网站”的感觉。
- **第1周**：租用云服务器。手动部署 Node.js 项目。配置域名和 HTTPS。
- **第2-4周**：配置完整的 持续集成 / 持续部署 流水线。建立监控和报警系统。
- **持续进行**：学习 Docker 容器化、Kubernetes 集群以及微服务架构。
