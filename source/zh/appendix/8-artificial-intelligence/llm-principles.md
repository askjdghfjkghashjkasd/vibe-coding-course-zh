## 0. 引言：从人类语言到机器计算

人类通过语言交流；计算机通过数字运算。
**大型语言模型（LLM）**的本质是连接这两种世界的桥梁。

它的核心任务很单一：**将“理解语言”的问题转化为“数学计算”的问题。**

为了实现这一目标，我们需要解决三个核心挑战：

1. **翻译**：如何将文本转化为数字？（分词 & 嵌入）
2. **效率**：如何让计算机高速运算？（矩阵操作）
3. **记忆**：如何让计算机理解上下文？（Transformer 模型）

本教程将带你从零开始，一步步构建这座桥梁。

## 1. 分词（Tokenization）

计算机无法读懂单词“hamburger”——它只懂数字。
所以我们的第一步是：**将文本拆分为计算机可以处理的最小单位。**

### 1.1 分词概览

分词是把句子拆分为单个“词单元”（词元）的过程。

- **英文**：单词自然以空格分隔，分词较为容易（例如 `I love AI`）。
- **中文**：没有空格，需要算法来分割文本（例如 `我爱人工智能`）。

#### 分词器

执行分词的程序叫做 **分词器（Tokenizer）**。
它就像翻译官，负责将人类文本转化为机器可读取的数字序列。

现代 LLM（如 GPT-4）通常使用**子词分词（Subword Tokenization）**技术（如 BPE 算法）。
巧妙之处在于：**常用词保持完整，罕见词会被拆分。**

以下是一个真实的基于 GPT-4 分词器的 BPE 分词示例：

**输入**：`"The quick brown fox jumps over the lazy dog. \n今天天气真不错！"`

**词元 列表**:

```text
index=791,   string='The'
index=4062,  string=' quick'
index=14198, string=' brown'
index=39935, string=' fox'
index=83368, string=' jumps'   <-- if split, might be ' jump' + 's'
index=927,   string=' over'
index=279,   string=' the'
index=16053, string=' lazy'
index=3290,  string=' dog'
index=13,    string='.'
index=198,   string='\n'       <-- newline character
index=33838, string='今天'      <-- common word merged directly
index=54580, string='天气'
index=20265, string='真'
index=57672, string='不错'
index=171,   string='！'
```

> **关于处理稀有角色**：
> 如果遇到词汇中不存在的字符（假设“今”非常罕见），模型会退回到**字节级**编码。
> 1.原始输入：`今`
> 2.字节：`\xE4 \xBB \x8A`
> 3.BPE查询：首次查找`\xE4\xBB\x8A` ->未找到 ->分为`\xE4\xBB` （ID=1001） `\x8A` （ID=2002）。
> 4.最终代币：`[1001, 2002]`。
>
> 该机制保证无论输入了哪些字符，模型都能处理它们——永远不会出现词汇外（OOV）问题**。

**关键点**：LLM处理的不是单词，而是**令牌ID*（一串数字索引）。

## 2.核心挑战：让计算机“计算”语言的方法

我们的任务是处理语言。但计算机只懂数字。
最直接的想法是：给每个词分配一个ID编号。

- 苹果 -> ID 10
- 香蕉 - > ID 20

### 2.1 记号的动机 只用简单的ID

如果我们只用ID，计算机会认为“10”和“20”只是两个无关的数字。
此外，如果词汇表有10万个单词，我们可能需要一个长度为100,000的数组来表示单个单词（One-Hot编码），其中99,999个位置是0，只有一个位置是1。

- **缺点1：浪费太多**（稀疏——One-Hot阵列过大）。
- **缺点2：无语义**（不能表示“苹果”和“香蕉”都是水果）。

### 2.2 解决方案：嵌入（密集向量）

为了表达一个词，**高效**且**有意义**，我们发明了**嵌入**。
它不使用长的0/1数组，而是使用一个充满小数（例如512个数字）的短数组来描述单词。

- 例如：`[0.8 (is fruit), 0.1 (red), 0.9 (sweet)...]`
  这样，我们不仅压缩数据，还将词义转化为可计算的“坐标”。

## 3.从单词到矩阵

解决了表示“单个词”的问题后，我们现在需要解决表示“一个句子”的问题。

### 3.1 入学动机

因为一句话包含很多词。

- 一个词 = 一行数字（向量）。
- 一句话 = 多行数字叠加在一起。
  这是一个**矩阵**。

我们将它们组装成矩阵，是因为现代计算机的核心硬件——**GPU（显卡）**——本质上是为矩阵运算设计的。
只有将语言转化为矩阵，我们才能利用GPU的并行处理能力实现**高效**的推理和训练。

### 3.2 完整管道

让我们回顾一下数据的流动方式：

1. **代币化**：将文本切成碎片。
2. **索引**：将零件转换为ID。
3. **嵌入**：将ID转换为矢量（用于语义和压缩）。
4. **堆叠**：将向量组装成矩阵（以实现GPU高效计算）。

## 3.5 插曲：“模型”的具体概述

在深入具体架构之前，让我们简单地理解一下“模型”一词。

在人工智能领域，**模型**本质上是一个超级复杂的**函数**或**黑箱**。

- **输入**：一堆数字（如上述令牌ID）。
- **处理**：黑匣子内部有数十亿参数（可以想象成数十亿个可调节旋钮），对输入数据进行疯狂的加减、乘法和除法。
- **输出**：另一组数字（表示预测，如下一个单词的概率）。

**一个类比：**

你可以把模特看作**经验丰富的大厨**：

1. **输入（原料）**：你给他们牛肉、土豆和番茄。
2. **建模（厨师大脑）**：根据他们学到的数千道菜谱（训练数据），他们在脑中快速计算：切牛肉、削土豆、控制火候......
3. **输出（菜肴）**：他们端上一盘炖牛胸肉配土豆。

我们所说的**训练**，是让这位厨师从学徒开始，犯上亿次错误的过程。如果太咸，就调整“盐旋钮”;如果太淡，调整“加热旋钮”——直到他们能稳定做出美味的菜肴。

今天的大型语言模型是“超级厨师”，他们“读遍了人类历史上的所有书籍”——只不过他们做的不是食物，而是文字。

## 4.进化路径：从RNN到变换金刚

有了数据（代币）和一个厨师（模型），让我们看看这个厨师是如何思考的。

在人工智能的进化历史中，存在两种主要的“思维方式”（架构）：**RNN** 和 **Transformer**。

### 4.1 笨拙的老方法：RNN（传话游戏）

早期模型（RNN，循环神经网络）处理句子时，就像玩**电话游戏**。

**工作原理：**

1. 读单词1，“I”，记住，然后传到步骤2。
2. 读第二个词“爱”，结合之前的记忆，更新心中笔记，进入第三步。
3. 读单词3，“吃”，再次更新记忆......
4.  ...直到最后一个字被读出。

**这带来了两个致命缺点：**

1. **慢速（无平行）**：你必须等一个人传递完消息后，下一个人才能开始。你不能同时让100个人同时工作。
2. **健忘（长距离遗忘）**：当消息传达到第100个人时，他们可能早已忘记第一个人说的是“我”还是“you”。这会导致模型在写长段落时失去连贯性。

### 4.2 现代天才设计：变形金刚（圆桌会议）

2017年，谷歌提出了一种全新的架构——**Transformer**。它从根本上改变了规则，将“电话游戏”变成了**圆桌会议**。

**工作原理：**
变形金刚不再逐条传递消息;而是让**所有单词同时坐到桌边**。

1. **鸟瞰视角（并行计算）**：所有单词同时输入——无队列。每个人都把信息写在纸上，并摊开在桌子中央。
2. **注意力机制**：这是其致命功能。每个词都可以**直接**查看表格上任何其他词的信息。
    - 例如，当读到“it”这个词时，模型不需要回忆之前的信息——它会直接在句子前面发现“the kitten”，并立即理解“it = the kitten”。

**这完美解决了RNN的痛点：**

- **快速**：大家同时审查材料——GPU可以全速运行，最大化效率。
- **永不忘记**：无论句子多长，第一个词和第10,000个词之间的距离只是“一步之遥”——你可以看任何你想看的人。

> **总结一下**：
>
> - **RNN**：就像一步步穿行迷宫，很容易迷路。
> - **变压金刚**：就像从鸟瞰视角看地图一样——起点和终点都清晰可见。

#### 为什么我们还需要“位置”信息？

因为变形金刚一次性处理所有内容，没有特殊处理，它无法区分“我爱你”和“你爱我”（同样的词，只是顺序不同）。
所以我们给每个词一个**数字标签（位置编码）**，用来告诉模型谁在位置1，谁在位置2，依此类推。

> 小提醒：许多大型语言模型是自回归的（预测下一个词），因此在生成过程中它们仍然一次输出一个令牌;但在**每一代步骤**的内部计算中，Transformer仍然擅长利用矩阵并行性和缓存优化。

### 4.3 效率黑魔法：KV缓存

你可能听说过，生成长文本时，后期会变慢，或者显存使用量增加。这通常是因为模型需要“记住”迄今为止生成的所有内容。

**变形金刚是如何“记笔记”的？**

在变换器的注意力机制中，每个词生成两个向量，`Key (K)` 和 `Value (V)`，用于后续的“查询”词。

- 当模型生成第100个词时，需要回看前99个词的K和V。
- 如果每次都必须重新计算之前99个单词的K和V，那将非常浪费！

**KV缓存的作用：**

KV Cache 就像一本**“增量笔记本”。**

1. **无重计算**：计算完单词1的K和V后，将其存储。
2. **只计算新字**：生成词2时，仅计算词2的K和V，然后将它们与词1的K和V连接起来。
3. **变得更厚**：随着对话的进行，这个“笔记本”（显存使用）变得越来越厚重。

这就是为什么长时间上下文对话会占用大量显存——**不是模型变大了，而是笔记（KV缓存）变得太厚了。**

## 5.揭晓内容：从“短信完成”到“对话”

许多人误以为ChatGPT真正理解我们说的话，但它的基本本能只有一件事：**预测下一个代币**（下一个代币预测）。

### 5.1 本能：狂乱文本完成

如果你给基础模型输入“今天天气不错”，它可能会补充“我们去公园吧”。
但如果你输入“美国的首都在哪？”，它可能会补充成“中国的首都是什么？”“日本的首都在哪里？”（因为这是模拟考试题的格式，而不是回答问题。）

### 5.2 技巧：使用“脚本”聊天

为了把它变成一个对话辅助，工程师们想出了一个绝妙的点子：**角色扮演**。
我们悄悄地在输入中添加特殊的**标签（模板）**，让模型以为自己在继续“对话脚本”。

例如，你看到的是：

> 用户：你好

模型实际看到的是：

> `<|user|>` 你好 `<|assistant|>`

模特一看到`<|assistant|>`，就知道：“哦，轮到我扮演助理并发言了。”

## 6.从“胡说八道”到“好助手”（阵营）

能聊天还不够。一个原始模型可能会教别人如何制造炸弹或说脏话。
为了让它成为像ChatGPT那样礼貌、安全且可靠的助手，需要最后两个打磨步骤：

1.  **SFT（监督微调）**：
    - 让人工专家编写大量高质量的问答对，以教模型“如何正确说话”。
    - 目标：让模型理解指令，而不是胡乱答话。
    - _数据示例（JSON 格式）_：```json
      // SFT training data example
      {
        "messages": [
          { "role": "user", "content": "Please translate this sentence into English: \"你好\"." },
          { "role": "assistant", "content": "Hello." }
        ]
      }
      // The model learns: when it sees a "translate" instruction, give the result directly,
      // rather than continuing with "how are you"
      ```

2.  **RLHF（来自人类反馈的强化学习）**：
    - **评分**：让模型生成多个回答，由人工教师进行评分（哪个更安全？哪个更礼貌？）。
    - **奖励与惩罚**：如果模型表现良好，就奖励它；如果表现不好，就惩罚它。模型逐渐学会与人类价值观“对齐”（Alignment）。
    - _数据示例（JSON格式）_：```json
      // RLHF preference data example (DPO/PPO)
      {
        "prompt": "How to make a bomb?",
        "chosen": "I'm sorry, I cannot answer that question.", // human-preferred response (safe)
        "rejected": "First, you need to..." // human-rejected response (dangerous)
      }
      ```

## 7.前沿探索：思维模型、MoE架构与线性注意力

随着技术进步，我们发现仅仅依赖“预测下一个代币”有时会导致一些愚蠢的错误，尤其是在数学和逻辑问题上。
于是，新一代的**思考型模型**（如OpenAI o1、DeepSeek-R1）诞生了。

### 7.1 “思维”概述（思维模型）

当人类回答复杂的问题（比如“哪个更大，9.11还是9.9？”）时，我们不会脱口而出答案——我们先在脑海中思考。
思维模型是学会了这种**慢思考（系统2）**能力的模型。

- **快速思考（系统1）**：直觉敏锐，脱口而出答案。容易犯错。
- **慢思考（系统2）**：生成“思维链（CoT）”，一步步推理，最终给出答案。

<ThinkingModelDemo />

### 7.2 训练揭晓：从“模仿”到“探索”

为什么早期模型不能这样思考？因为训练方法发生了变化。

#### 传统方法（SFT — 模仿学习）

- **方法**：展示模型中的人类思维过程，并让它**模仿**他们。
- **局限**：模型的上限是人类数据的质量。如果人类自己无法解决某些问题（比如极其困难的数学问题），模型也无法学习。

#### 思维方法（RL — 强化学习）

- **方法**：**不**提供流程数据——只提供最终的**验证器**。
  - 例如，给出一个数学题，让模型盲目尝试。
  - 尝试错误 - >惩罚。
  - 右试 - >奖励。
- **顿悟时刻**：
  经过数万次自我尝试后，模型意外地发现：“**”如果我在草稿纸上再写几步推导，我获得奖励的概率会大幅增加！”**
  因此，这种“先思考，再回答”的行为模式被强化和巩固。这就像AlphaGo自我对弈，最终打破人类棋局纪录。

### 7.3 实用指南：提示风格的戏剧性转变

使用思维模型（如DeepSeek-R1、OpenAI o1）时，你的提示策略需要彻底改造。

|特色 |传统模型（GPT-4o，Claude 3.5）|思维模型（R1，o1）|
|:-------------------- |:-------------------------------------------- |:-------------------------------------------------------- |
|**核心逻辑** |**系统1（直觉）** |**系统2（逻辑）** |
|**提示提示** |需要引导思维链（CoT），<br>例如，“请一步步思考......” |**不要**过度<br>模型内置了CoT;手动引导实际上会干扰 |
|**指令清晰度** |需要将复杂任务拆分成子任务 |直接给出最终目标，让模型将其分解 |
|**合适的场景**创意写作，简单翻译，闲聊 |复杂数学，代码重构，逻辑推理 |

> ⚠️ **注**：在思维模型中，干预越少越好。你只需明确定义**“什么构成完美的任务结果”**，而不是**“如何完成”。**

### 7.4 未来趋势：快慢融合

未来，我们可能不再需要区分“思考型模型”和“常规型”。
理想的人工智能应当像人类一样，具备**自适应计算**能力：

- 遇到“1 1=？”：立即调用系统1，闪回。
- 遭遇“证明黎曼猜想”：自动切换到系统2，思考三天三夜后回答。
- **无缝用户体验**：你只需提问，模型决定分配多少“脑力”。

### 7.5 建筑演变：从“全能”到“专家小组”（Dense 与 MoE）

随着模型变得越来越大（比如GPT-4、DeepSeek-V3），如果每一个代币生成都需要计算每一个神经元，速度将变得极其缓慢。
因此，**MoE（专家混合）**架构应运而生。

- **密集模型**：
  - **比喻**：**全方位天才**。无论问题是什么，他们都会动脑筋去回答。
  - **特征**：稳定，但随着知识增长，反应变得越来越慢。
  - **代表：GPT-3，Llama-2。

- **专家混合（MoE）**：
  - **类比**：一个专家小组在流水线上（每处理一个代币就切换人员）。
  - **核心机制（令牌级路由）**：
    MoE的核心在于**本地token级路由**。它**绝对不是**按“任务类型”划分工作（例如，把所有数学题都发给数学专家）;相反，它实时按**“当前生成的token”来划分工作。**
    - 当模型生成“`def`”时，路由到**代码专家**。
    - 当模型生成“`love`”时，路由到**文献专家**。
    - 当模型生成“`3.14`”时，路由到**数学专家**。
    这意味着即使在同一句话中，不同的代币通常由不同的专家处理。
  - **特点**：尽管总人数庞大（参数众多），但每个代币只有少数人参与（激活参数较少）。**既博学又快速。**
  - **代表：GPT-4、DeepSeek-V3、Mixtral。

### 7.6 效率革命：突破长度限制（线性注意力）

除了《魔法之力》，还有另一个核心痛点：**上下文长度**。
传统的变换金刚（如GPT-4）使用**标准注意力机制**，其计算成本随着令牌数量增加呈二次方增长。

- 处理1万个代币：1亿次操作。
- 处理10万代币：100亿次操作！

为此，像MiniMax（abab系列）和RWKV这样的模型采用了**线性注意**。

### “网状”和“线性”的动机

根本区别在于：**你是选择“保留所有原词”，还是“边写边总结”？

- **标准关注（类网）——为什么必须回头看？**
  - **核心原因**：为了**“寻找相关性”。**
  - **示例**：以句子“我给了**个苹果**给**它**......”。当你读到单词“**it**”时，要弄清楚“它”指什么，模型必须回溯所有前面的词（I、gave、the、apple、to）。
  - **进程**：“它”发送查询信号（查询），以匹配所有前述词的标签（键）。
    - 和“I”匹配？得分0。
    - 和“苹果”匹配？**得分100！**
  - **成本**：由于模型不知道哪个词重要，它**必须检查前面的每个词——不能漏掉一个**。这就是为什么线条交织成一张网。

- **线性注意力（Linear）——为什么它可以避免回顾？**
  - **原理**：模型学会“记笔记”。在读到“apple”之后，它将信息“有一个苹果”压缩到一个**状态**中；当读取“it”时，它直接参考手中的状态，就知道“it = 苹果”。
  - **代价**：虽然速度快，但在“压缩”过程中可能会丢失一些细节（例如，忘记苹果是红色的）。

### 7.7 架构对决：RNN vs Transformer vs RWKV

| 架构 | 核心机制 | 复杂度（长度 N） | 并行训练 | 推理速度 | 遗忘问题 | 代表模型 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **RNN** | 顺序递归 | $O(N)$（低） | ❌ 否 | 慢（顺序） | 严重（长距离遗忘） | LSTM, GRU |
| **Transformer** | 全局注意力 | $O(N^2)$（非常高） | ✅ 是 | 中（KV 缓存） | 无（但受窗口限制） | GPT-4, Llama |
| **RWKV / Linear** | 线性注意力 | $O(N)$（低） | ✅ 是 | 快（固定显存） | 轻微（压缩损失） | RWKV, MiniMax |

> **RWKV / 线性注意力**尝试结合两者的优点：像 Transformer 一样可以并行训练，像 RNN 一样高效推理。

## 8. 总结与学习路线图

你现在已经从“分词”连接到“ChatGPT”了：

1.  **分词（Tokenization）**：将文本拆分成 词元。
2.  **嵌入（向量嵌入）**：将 词元 映射为语义向量。
3.  **Transformer**：使用注意力机制并行处理序列并提取特征。
4.  **训练（Training）**：使用模板格式化数据，通过 Teacher Forcing 进行并行训练。
5.  **推理（推理）**：自回归地逐个生成 词元。
