# RAG 原理：检索增强生成

::: tip 前言
**为什么 ChatGPT 有时会“自信地编造信息”？** 大型语言模型的知识来自训练数据，但训练数据有截止日期，并不包含贵公司的内部文档。RAG（检索增强生成）是解决这一问题的核心技术——让 AI 在回答前可以“查找参考资料”。
:::

## 0. 概述：大型模型为何需要“查找参考资料”

想象你是一位博学的教授，读过无数书籍。但如果有人问你“昨天的销售额是多少”，你肯定回答不上——因为这些信息不在你读过的书里。

大型语言模型正面临同样的困境：

- **知识有截止日期**：GPT-4 的训练数据有截止时间，因此它不知道之后发生的事情  
- **缺乏私有知识**：贵公司的内部文档、产品手册和客户数据模型从未见过  
- **容易产生幻觉**：当模型对答案不确定时，它倾向于“编造”一个看似合理的回复

::: tip RAG 核心理念
RAG 的解决方案非常直观：**在让模型回答之前，先帮它找到相关的参考资料。** 就像开卷考试——你不需要记住所有内容，只需要知道在哪里找和如何查。

RAG = 检索 (Retrieval)   增强 (Augmented)   生成 (Generation)
:::

## 1. RAG 基本工作流程：索引、检索、生成

RAG 的工作流程可以分为两个阶段：**离线索引**和**在线查询**。

离线阶段就像图书馆的编目工作——对所有书籍进行分类、编号并上架，以便将来轻松检索。在线阶段则是读者来图书馆查找信息的过程——根据问题找到相关书籍，然后综合信息提供答案。

<RAGPipelineDemo />

::: 提示 三个核心阶段
1. **索引阶段**：加载、清理并分块原始文档，然后通过嵌入模型将其转换为矢量，并存储到矢量数据库中。这是一个一次性的准备步骤。
2. **检索阶段**：用户提问时，也将问题转换为矢量，并在矢量数据库中搜索最相似的文档块。
3. **生成阶段**：将检索到的文档块与用户的问题合并为提示词，并传递给大型模型生成最终答案。
:::

|阶段 |输入 |输出 |关键技术 |
|------|------|------|---------|
|索引 |原始文档 |向量数据库 |文本分块，嵌入模型 |
|检索 |用户问题 |顶K文档块 |向量相似度，重新排序 |
|生成 |问题上下文 |最终答案 |提示工程，LLM |

## 2.文本分段：把大象放进冰箱

文本分块是RAG中最容易被忽视但影响最大的步骤。为什么需要分块？因为大型模型的上下文窗口有限，我们无法塞满整本书。更重要的是，**分块质量直接决定检索质量**。

想象一下，在图书馆里寻找某本书中的某个特定知识。如果整本书是一个“块”，找它也没用——你仍然得翻整本书。但如果是按章节甚至段落分块，你就能精准找到所需的内容。

<ChunkingStrategyDemo />

::: 提示 选择分块策略
- **固定大小分块**：按字符数或令牌数划分——简单但可能破坏语义
- **递归分块**：先按段落拆分;如果段落过长，按句子分段——保持语义完整性
- **语义分块**：使用嵌入模型检测语义边界，在相似性急剧下降处进行分裂
- **文档结构分块**：使用Markdown标题和HTML标签等结构信息进行分块

没有“最佳”分块策略，只有最适合你数据的那一种。一般来说，从递归分块开始，块大小200-500个token，重叠比例为10-20%。
:::

## 3.检索技巧：寻找最相关内容的方法

分块完成后，下一个关键问题是：**当用户提问时，如何从数千个文档片段中找到最相关的块？**

这就像在一个庞大的图书馆里搜索书籍。你可以按书名关键词搜索（关键词检索）、描述你想要的内容并让图书管理员协助（语义检索），或者最棒的是结合两种方法（混合检索）。

<检索演示 />

|检索方法 |原理 |优点 |缺点 |
|---------|------|------|------|
|关键词检索（BM25）|基于词频和反文档频率 |精确匹配，快速 |无法理解语义，同义词失败 |
|向量检索 |基于嵌入向量的余弦相似性 |理解语义，支持模糊匹配 |对专有名词敏感度较低 |
|混合检索 |融合关键词和向量检索结果 |平衡精度与语义 |需要权重调整，复杂度更高 |

::: 提示 重排序
在检索候选文档之后，通常需要一个“重排序”步骤。初步检索侧重于召回（尽量不漏掉任何信息），而重排序侧重于精确度（将最相关的内容排在最前）。常用的重排序模型包括 Cohere Rerank 和 BGE Reranker，它们使用交叉编码器对查询-文档对进行精细评分。
:::

## 4. 架构演变：从简单到智能

RAG 技术仅在两年内就经历了三代演变，每一代都解决了上一代的痛点。

<RAGArchitectureDemo />

::: 提示 三代 RAG 对比
- **原始 RAG (2023)**：最基础的“索引 → 检索 → 生成”工作流程。实现简单但效果有限。问题包括：检索质量不稳定、无法处理复杂查询、容易引入噪声上下文。
- **高级 RAG (2024)**：基于原始 RAG，增加了查询重写、混合检索、重排序、上下文压缩等优化步骤，显著提升了检索精度和生成质量。
- **模块化 RAG (2025)**：将 RAG 拆分为可插拔模块，支持路由决策、自适应检索、自我反思等高级功能。可根据查询类型动态选择最优处理流程。
:::

## 5. RAG vs 微调：选择指南

当你希望大型模型掌握特定领域知识时，通常有两条路径：RAG 和微调。它们不是互斥的，而是互补的。

打个比方：**微调就像送学生去培训班**，将知识内化到大脑中；**RAG 就像给学生参考书**，考试时可以查阅。两种方法各有优缺点，关键取决于你的具体需求。

<RAGvsFineTuningDemo />

| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时更新；只需修改文档 | 需要重新训练 |
| 成本 | 低（无需 GPU 训练） | 高（需要训练资源） |
| 可解释性 | 高（来源可追踪） | 低（知识内化在权重中） |
| 适用场景 | 知识库问答、文档检索 | 风格迁移、特定任务优化 |
| 幻觉控制 | 较好（有参考依据） | 一般（仍可能出现幻觉） |

::: 提示 实用建议
在大多数场景下，**先尝试 RAG**。RAG 的优势包括：无需训练、实时知识更新、答案来源可追踪。只有在需要改变模型“行为模式”（如输出格式、语言风格或推理方式）时才考虑微调。最强的解决方案通常是 **RAG + 微调** 结合。
:::

## 总结

RAG 目前是将大型模型投入生产中最实用的技术之一。其核心价值在于：使模型答案可验证、知识可实时更新、幻觉得到有效控制。

本章关键要点：

1. **RAG解决的核心问题**：模型知识过时、缺乏私有数据，以及容易产生幻觉
2. **三阶段工作流程**：索引（离线准备）→ 检索（在线搜索）→ 生成（综合回答）
3. **分块是基础**：分块质量直接决定检索质量；选择合适的分块策略至关重要
4. **检索是关键**：混合检索 + 重排序目前是性能最好的组合
5. **架构在演变**：从简单RAG到模块化RAG，系统变得越来越智能和灵活
6. **RAG和微调是互补的**：在大多数场景下先尝试RAG；当需要改变模型行为时考虑微调
