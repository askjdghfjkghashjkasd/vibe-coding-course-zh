## 1.端口概述（IP是建筑，端口是房间号）

### 1.1 直觉类比

想象一下，服务器是一栋建筑：

- **IP地址**（例如，`192.168.1.100`）是建筑的街道地址——它告诉你“该去哪栋楼”。
- **端口号**（例如，`:80`）是建筑内的房间号——它告诉你“应该进入哪个房间”。

一栋建筑可以同时拥有餐厅（80号房间）、咖啡馆（443号房间）和办公室（22号房间）。同样，一台计算机可以同时运行网页服务器、数据库和SSH服务，每个服务使用不同的端口。

### 1.2 端口编号范围

端口号为整数，介于**0至65535**之间（共65,536个端口）。这些端口分为三个范围：

|范围 |价值 |目的 |示例 |
|:--- |:--- |:--- |:--- |
|**系统端口** |0 – 1023 |保留给标准协议;普通用户无法自由使用它们 |80（HTTP），443（HTTPS），22（SSH）|
|**注册端口** |1024 – 49151 |注册用于通用应用 |3306（MySQL），5432（PostgreSQL），6379（Redis）|
|**动态端口** |49152 – 65535 |操作系统临时分配 |当浏览器发出请求时，操作系统会随机分配源端口 |

> 为什么你的开发服务器喜欢使用3000、5173或8080？因为它们都在“注册端口”范围内——不需要管理员权限就能监听，而且不太可能与系统服务冲突。

## 2.localhost（寻找自我）概述

### 2.1 “环回”的核心概念

`localhost` 是一个特殊的域名，总是指向**你自己的电脑**。

当你在浏览器中输入`http://localhost:3000`时，会发生以下情况：

1. 浏览器问操作系统：“`localhost`的IP是什么？”
2. 操作系统直接回答：“`127.0.0.1`”（无需通过网络查找DNS）
3. 数据包发送到 `127.0.0.1`，但**从未真正离开你的机器**
4. 操作系统通过**环回接口“回环”数据包
5. 端口3000监听的程序接收请求并发送响应

**整个过程不经过任何网络线、路由器或互联网连接。**

### 2.2 `localhost` 对 `127.0.0.1` vs `0.0.0.0`

这三个概念常被混淆，但它们的含义完全不同：

| 符号 | 含义 | 谁可以访问 |
| :--- | :--- | :--- |
| `localhost` / `127.0.0.1` | 回环地址，仅本地机器可用 | 仅您自己的电脑 |
| `0.0.0.0` | 监听所有网络接口 | 本地机器  局域网的其他设备 |
| `192.168.x.x` | 局域网IP | 局域网内的设备 |

**实际场景**：

```bash
# Only you can access (secure, good for development)
npm run dev -- --host localhost

# Your phone can also access (good for mobile debugging)
npm run dev -- --host 0.0.0.0
```

> 许多框架（如 Vite、Next.js）默认监听 `localhost`，所以即使你的手机在同一个 WiFi 上，也无法访问你的开发服务器。想在手机上调试吗？只需添加 `--host` 标志。

## 3. 端口冲突：最常见的开发环境问题

### 3.1 端口冲突发生的原因

**一个端口一次只能被一个程序监听。** 就像一个房间一次只能住一家人。

如果你尝试在同一个端口启动第二个服务，你会看到这个经典错误：

```
Error: listen EADDRINUSE :::3000
```

用通俗的语言说：**“3000号端口已经被占用——你进不去！”**

常见的冲突场景：
- 之前的开发服务器没有正确关闭，仍在后台运行
- 两个不同的项目使用了相同的默认端口
- 系统某些服务已经占用了你想使用的端口

### 3.2 排查与解决

当你遇到端口冲突时，排查步骤非常一致：

**macOS / Linux:**```bash
# Step 1: Check who is using port 3000
lsof -i :3000

# Step 2: Once you have the PID, force kill it
kill -9 <PID>
```

**Windows：**```bash
# Step 1: Check who is using port 3000
netstat -ano | findstr :3000

# Step 2: Kill the process
taskkill /PID <PID> /F
```

> 许多现代框架（如 Vite、Create React App 等）在检测到端口冲突时会自动询问“切换到另一个端口吗？”。但理解底层原理有助于你排查那些框架无法处理的棘手问题。

## 4. 开发中的同源策略与 CORS

### 4.1 “源”的概述

浏览器有一种安全机制，称为**同源策略（Same-Origin Policy）**：仅当**协议、域名和端口**均相同，两个 URL 才被视为“同源”。

| URL A | URL B | 同源？ | 原因 |
| :--- | :--- | :--- | :--- |
| `http://localhost:5173` | `http://localhost:5173/about` | ✅ 同源 | 协议、域名、端口完全相同 |
| `http://localhost:5173` | `http://localhost:3000` | ❌ 不同源 | **端口不同**（5173 vs 3000） |
| `http://localhost:5173` | `https://localhost:5173` | ❌ 不同源 | **协议不同**（http vs https） |

### 4.2 前后端分离时总会遇到的 CORS 问题

当你的项目架构是：

```
Frontend (Vite)  →  http://localhost:5173
Backend (Express) →  http://localhost:3000
```

前端页面从 `:5173` 加载，然后使用 `fetch('/api/users')` 请求 `:3000` 上的 API — **不同的端口会触发跨域限制！**

**两种常见的解决方案：**

**方案 1：在后端配置 CORS**```javascript
// Express backend
app.use(cors({ origin: 'http://localhost:5173' }))
```

**选项 2：在前端配置代理（推荐）**```javascript
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': 'http://localhost:3000'
    }
  }
}
```

代理的工作原理：Vite 开发服务器会“代表你转发”请求。浏览器认为它正在与 `:5173`（同源）通信，而 Vite 在幕后偷偷地将请求转发给 `:3000`。

## 6. 术语参考

| English Term | Chinese Translation | Explanation |
| :--- | :--- | :--- |
| **Port** | 端口 | 一个 0–65535 的数字，用于区分同一台机器上的不同网络服务。每个服务在端口上“监听”，等待客户端连接。 |
| **localhost** | 本地主机 | 一个特殊的域名，总是指向本地机器（127.0.0.1）。用于在无互联网连接的情况下访问运行在自己机器上的服务。 |
| **Loopback Interface** | 环回接口 | 操作系统中的一个虚拟网络接口。发送到 127.0.0.1 的数据包从不离开本机，而是通过该接口“回环”。 |
| **EADDRINUSE** | 地址已被使用 | 来自 Node.js / 操作系统的错误，表示你想监听的端口已被其他程序占用。 |
| **CORS** | 跨域资源共享 | 浏览器安全机制。当前端页面尝试请求来自不同源（不同协议/域名/端口）的 API 时，后台必须明确授权。 |
| **Same-Origin Policy** | 同源策略 | 浏览器安全的基石：只允许具有相同协议、域名和端口的请求之间自由通信，阻止跨源的数据读取。 |
| **Proxy** | 代理 | 在开发环境中，代理服务器将浏览器的请求转发到后台，绕过浏览器的同源限制。 |
| **0.0.0.0** | 所有接口 | 当服务监听 0.0.0.0 时，它接受来自任意网络接口（本机、局域网等）的连接。 |
| **Well-known Ports** | 知名端口 | 0–1023 号端口的统称，保留给标准协议，如 HTTP (80)、HTTPS (443)、SSH (22)。 |
| **PID** | 进程 ID | 操作系统分配给每个运行程序的唯一编号，用于管理和终止进程。 |
| **lsof** | 列出打开的文件 | macOS/Linux 命令，用于查看哪个进程正在使用特定端口 (`lsof -i :port_number`)。 |
| **HMR** | 热模块替换 | 开发服务器功能：当你修改代码时，浏览器自动更新，无需手动刷新。底层通过 WebSocket 通知实现。 |

## 总结

端口和本地主机是开发环境中最基础、最常遇到的概念：

- **Port（端口）** = 区分机器上不同服务的“房间号”（0–65535）
- **localhost（本地主机）** = 特殊的“找自己”地址（127.0.0.1），数据永远不会离开你的机器
- **端口冲突** 本质上是“一个房间号只能有一个标识”
- **CORS（跨域资源共享）** 本质上是“不同端口 = 不同源”，需要 CORS 或代理来解决

记住这四点，你就能快速识别开发环境中大多数网络问题的原因。
