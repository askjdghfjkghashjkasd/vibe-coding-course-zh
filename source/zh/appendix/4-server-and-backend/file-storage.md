## 0.大局观：你不把文件本地存储在服务器上，而不是被打的动机

启动项目时，将用户上传的文件保存到本地服务器目录中是最直观的方法。但随着项目的发展，你会遇到一系列问题：

- **磁盘空间有限**：服务器磁盘总是满;扩展容量很麻烦
- **多服务器非共享**：通过负载均衡，用户请求可能访问不同服务器，且找不到文件
- **无备份**：如果服务器宕机，文件就消失
- **无CDN**：全球访问单一服务器的用户速度较慢

::: 提示 对象存储的核心价值
对象存储（如AWS S3、阿里云OSS）解决了所有这些问题：**无限容量、全球可访问、自动备份、原生CDN支持**。它已成为互联网应用中文件存储的事实标准。
:::

## 1.存储类型比较：块、文件、对象

计算机世界中主要有三种存储类型，每种类型在不同层次上解决问题。

<FileStorageTypeDemo />

|维度 |块存储 |文件存储 |对象存储 |
|------|--------|---------|---------|
|数据单元 |固定大小块 |文件目录 |对象（键值） |
|访问协议 |iSCSI/FC |NFS/SMB |HTTP REST API |
|性能 |最高（毫秒） |中等 |较低（但足够） |
|可扩展性 |有限 |中等 |几乎无限 |
|成本 |最高 |中等 |最低 |
|典型用例 |数据库 |共享文件 |图片/视频/备份 |

::: 提示 简单助记法
- **块存储**就像硬盘——用于数据库
- **文件存储**就像网络共享文件夹——用于在多个服务器间共享配置
- **对象存储**就像云存储——用于用户上传的图片和视频
:::

## 2.对象存储核心概念

对象存储的数据模型非常简单：**Bucket** 是容器，**Object** 是文件，每个对象由唯一的 **Key** 标识。

```
my-app-bucket/                    ← Bucket
├── avatars/user-123.jpg          ← Object Key
├── avatars/user-456.png          ← Object Key
├── reports/2024/q1-report.pdf    ← Object Key ("directory" is just a Key prefix)
└── uploads/temp/file.zip         ← Object Key
```

|概念 |描述 |示例 |
|------|------|------|
|桶 |存储容器，全球唯一名称 |`my-app-prod`， `company-assets` |
|对象 |存储文件本身的元数据 |一张图片，PDF |
|关键 |对象的唯一标识符 |`avatars/user-123.jpg` |
|元数据 |关于对象的额外信息 |内容类型，自定义标签 |
|ACL |访问控制列表 |公开读取，私有 |
|预签名网址 |临时授权访问链接 |上传/下载链接有效期15分钟 |

::: 提示对象存储没有真正的“目录”
`avatars/user-123.jpg` — `avatars/` 部分不是目录，只是键前缀。对象存储是平面结构;所有对象都处于同一级别。控制台中显示的“文件夹”只是按前缀进行视觉分组。
:::

## 3.文件上传解决方案：谁上传文件

文件上传有两种主流方式：服务器端中继和客户端直接上传。对于大多数场景，**客户端直接上传**是更好的选择。

<FileUploadFlowDemo />

::: 提示 客户端直接上传的优势
1. **节省服务器带宽**：文件不会通过你的服务器;它们直接传送到OSS
2. **避免超时**：大文件上传不会触发Nginx/网关超时限制
3. **降低服务器负载**：服务器只需发放凭证，无需处理文件流
4. **支持可恢复上传**：OSS原生支持多部分上传;前端可以实现可恢复上传

实现步骤：前端向后端请求预签名的 URL，→前端使用该 URL 直接上传到 OSS，→OSS 回调通知后端
:::

## 4.CDN加速：为全球用户打造快速

当用户分布在全球时，从单一来源服务器下载文件会很慢。CDN（内容分发网络）在全球部署边缘节点，将文件缓存在离用户最近的节点，显著降低访问延迟。

<CDNAccelerationDemo />

|加拿大国家概念 |描述 |
|---------|------|
|边缘节点 |分布在全球的缓存服务器 |
|原点取用 |当边缘节点没有缓存副本时，它会向原服务器 |
|缓存命中率 |由边缘节点直接服务的请求比例;越高越好 |
|TTL |缓存有效期;过期后需要新的起点取指 |
|缓存失效 |主动清除边缘节点缓存以使新文件生效 |

::: 提示 CDN最佳实践
- **在文件名中添加哈希**：`logo.a3f2b1.png` 代替 `logo.png`，这样更新文件时无需使缓存失效
- **设置合理的TTL**：静态资产（JS/CSS/图片）TTL较长（1年），HTMLTTL短（5分钟）
- **启用 Gzip/Brotli 压缩**：压缩后文本资源可减少 60-80%
:::

## 5.最佳实践

|实践 |描述 |示例 |
|------|------|------|
|密钥命名规范 |使用有意义的前缀来组织文件 |`{type}/{date}/{uuid}.{ext}` |
|避免使用热点密钥 |不要从递增的数字开始 |使用 UUID 或哈希前缀 |
|最低必要权限 |桶默认为私有 |仅对需要为公共的文件设置公开读取 |
|生命周期规则 |自动清理过期文件 |临时文件在7天后自动删除 |
|CORS 配置 |前端直接上传需要设置 CORS |允许你的域名进行 PUT/POST |
|服务器端加密 |为敏感文件启用SSE |SSE-S3 或 SSE-KMS |

## 摘要

文件存储是每个网页应用程序都会遇到的一个基本问题。对象存储凭借其容量无限、成本低廉和高可用性，已成为互联网应用的标准选择。

本章主要内容要点：

1. **三种存储类型**：块存储用于数据库，文件存储用于共享，对象存储用于用户文件
2. **对象存储模型**：Bucket（存储桶）  Key（键）  Object（对象），扁平结构，HTTP API 访问
3. **客户端直接上传**：预签名 URL 方法——文件无需经过服务器，高效且节约资源
4. **CDN 加速**：边缘节点缓存  文件名哈希，使全球用户访问更快
5. **安全与管理**：最小必要权限、生命周期规则、服务器端加密
