# API 入门：从零理解程序间通信

::: tip 🎯 核心问题
**什么是 API？** 这就像在问：餐厅应该如何设计菜单，让顾客一眼就能看明白？服务员应该如何接单而不出错？API 解决了“程序之间如何通信”的问题。从你第一天写代码起，你就已经在使用 API 了——只是你可能没有意识到而已。
:::

## 0. 初学者常见的三个困惑

**困惑 1：API 是高级内容吗？**

很多人认为 API 只适合高级工程师。但实际上你已经在使用 API：

```python
len("hello")        # This is a Python API
open("file.txt")    # This is also an API
requests.get(url)   # This is still an API
```

**困惑 2：Web API 和普通 API 有什么区别？**

| 类型 | 目标 | 通信方式 | 典型场景 |
| :--- | :--- | :--- | :--- |
| **函数 API** | 本地代码 | 函数调用 | `len()`, `open()` |
| **操作系统 API** | 操作系统 | 系统调用 | 文件 I/O，进程创建 |
| **Web API** | 远程服务器 | HTTP 请求 | 调用 AI 模型，获取天气 |

**困惑 3：我应该使用 HTTP 还是 SDK？**

```python
# HTTP approach: handle all details yourself
import requests
response = requests.post(
    "https://api.deepseek.com/v1/chat/completions",
    headers={"Authorization": "Bearer sk-xxx"},
    json={"model": "deepseek-chat", "messages": [...]}
)
result = response.json()["choices"][0]["message"]["content"]

# SDK approach: let the butler handle it
from openai import OpenAI
client = OpenAI(api_key="sk-xxx")
response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[...]
)
result = response.choices[0].message.content
```

## 3.HTTP 方法：你“询问”或“执行”的概述

调用Web API时，你需要告诉服务器你想做什么。这就是HTTP方法的作用所在。

### 3.1 餐厅点餐比喻

|场景 |你会在现实生活中说什么？|HTTP方法 |
|:--- |:--- |:--- |
|你想看今天的菜单 |“服务员，让我看看菜单” |**获取** - 纯粹“询问”，不修改数据 |
|你想点宫保鸡丁 |“我要宫保鸡丁” |**帖子** - “做”某事，生成数据 |
|你想换菜 |“把宫保鸡丁改成酸甜猪肉” |**PUT** - 替换数据 |
|你想改变味道 |“宫保鸡丁里不加花生” |**补丁** - 部分修改 |
|你不想要了 |“算了，取消那道菜” |**删除** - 删除数据 |

<HttpMethodsDemo />

::: 关于幂性特征的警告
**幂等性**：多次执行是否会产生相同的结果？

- **幂零操作**（GET/PUT/DELETE）：点击10次与点击一次结果相同
- **非幂等操作**（POST）：点击10次可能生成10个命令

**解决方案**：使用唯一ID进行POST操作以防止重复处理。
:::

### 3.2 HTTP 方法快速引用

|方法 |目的 |幂零 |安全 |典型场景 |
|:--- |:--- |:--- |:--- |:--- |
|**获取** |检索资源 |是的 |是的 |查询列表，查看详情 |
|**发帖** |创建资源 |不 |不 |添加用户，提交订单 |
|**PUT** |完整更新 |是的 |不 |替换整个用户配置文件 |
|**补丁** |部分更新 |不 |不 |只需修改昵称 |
|**删除** |删除资源 |是的 |不 |删除用户，取消订单 |

## 4.HTTP 状态码：服务器概述

当服务器响应时，首先返回一个状态码，告诉你请求是否成功。

### 4.1 状态代码分类

<StatusCodeCategories />

### 4.2 常见状态代码解析

|状态代码 |含义 |典型场景 |客户端处理 |
|:--- |:--- |:--- |:--- |
|**200 OK** |成功 |请求正常处理 |显示数据 |
|**201 已创建** |成功创建 |POST 请求成功创建资源 |重定向到新资源 |
|**400个错误请求** |请求格式错误 |参数缺失或格式错误 |检查参数 |
|**401 未授权** |未认证 |未提供有效API密钥 |引导用户登录 |
|**403 禁止** |无权限 |API 密钥无权访问此资源 |显示权限不足 |
|**404 未找到** |未找到 |请求的地址或资源不存在 |检查网址 |
|**429 请求过多** |请求过多 |速率超过限制 |稍后重试 |
|**500 内部服务器错误** |服务器错误 |服务器端问题 |告诉用户稍后重试 |

## 5.HTTP 与 SDK：自己跑腿还是让管家处理

### 5.1 两种呼叫方式的比较

| |🏃 **HTTP API** |🤵**SDK** |
|:--- |:--- |:--- |
|**比喻** |自己跑腿 |管家处理 |
|**优点**✓ 支持任何语言 <br>✓ 完全控制请求细节 <br>✓ 无额外依赖 | ✓ 简洁易读的代码 <br>✓ 自动认证 <br>✓ 内置错误重试 |
|**缺点**✗ 需要处理所有细节<br>✗ 冗长且易出错的代码 | ✗ 需要安装依赖<br>✗ 可能存在版本问题 |
|**代码示例**`requests.post(url, json=..., headers={...})` |`client.chat.completions.create(...)` |

### 5.2 选择方法

|情景 |推荐方法 |原因 |
|:--- |:--- |:--- |
|**快速开发** |SDK |自动处理认证、错误和重试 |
|**学习原理**HTTP|理解底层机制 |
|**不支持的语言** |HTTP |适用于任何语言 |
|**需要定制** |HTTP |对每个细节的灵活控制 |

## 6.阅读API文档的方法

API文档就像手册和菜单的结合。你不需要从头到尾读完——只要学会“在字典里查找东西”就行。

### 6.1 文档阅读清单

打开任何API文档（比如OpenAI或DeepSeek），你只需要找到以下内容：

<ApiDocumentDemo />

| 项目 | 描述 | 示例 |
| :--- | :--- | :--- |
| **基础 URL** | API 的根地址 | `https://api.deepseek.com` |
| **认证** | 如何证明你的身份 | `Authorization: Bearer sk-xxx` |
| **端点** | 特定端点列表 | `/v1/chat/completions` |
| **参数** | 必填/可选参数 | `model`（必填），`temperature`（可选） |
| **响应** | 返回的数据结构 | `{"choices": [...]}` |

### 6.2 阅读文档的步骤

1. **找到基础 URL** - 这是所有请求的前缀
2. **了解认证方法** - API Key 在 Header 还是 Query？
3. **找到所需端点** - 你想调用的具体端点
4. **检查请求参数** - 哪些是必填的？哪些是可选的？
5. **了解响应格式** - 数据是如何组织的？

## 8. 总结

::: info 关键要点
1. **API 就像喇叭**，帮助你将信息传递给其他代码或远程服务器
2. **你已经使用过 API**，从 `len()` 到 `open()`，它们都是 API
3. **Web API 是超级能力**，让你调用数千英里之外的超级计算机
4. **SDK 是好管家**，有 SDK 可用时就用它，而不是自己跑业务
5. **在文档中找三样东西**：地址、认证和参数
:::

在 AI 编程时代，你只需要记住这些核心概念，其他细节将由 IDE 和 AI 助手处理。
