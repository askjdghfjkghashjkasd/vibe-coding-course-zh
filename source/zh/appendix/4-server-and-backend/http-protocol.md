# HTTP 协议原则：前端-后端通信

::: 提示 核心问题
**HTTP 是如何工作的？** 这就像问：两个人如何进行对话？他们需要就语言、语法和对话规则达成一致。HTTP 是前端和后端之间的“对话协议”。
:::

---

## 0.HTTP的本质

**HTTP**（超文本传输协议）是前端-后端通信的基础协议。

### 0.1 通信类比

|会话元素 |HTTP 等价物 |描述 |
|:--- |:--- |:--- |
|语言 |HTTP协议 |双方都能理解的语言 |
|语法 |请求/回答格式 |如何“说话” |
|流程 |请求-回应模式 |一个问题，一个答案 |
|结束 |挂断 |TCP连接关闭 |

## 1.HTTP的发展历程

自1991年诞生以来，HTTP 经历了多次重大升级。

<HttpProtocolDemo />

### 1.1 版本对比

|版本 |年份 |核心改进 |关键特性 |
|:--- |:--- |:--- |:--- |
|**HTTP/0.9** |1991 |仅支持 GET |仅支持纯文本，无响应头 |
|**HTTP/1.0** |1996 |新增 POST/HEAD |每个请求一个 TCP 连接 |
|**HTTP/1.1** |1997 |持久连接 |保持活泼，每个连接需多次请求 |
|**HTTP/2** |2015 |复用 |二进制帧，头部压缩 |
|**HTTP/3** |2022 |基于 QUIC |UDP 传输，解决线路头阻塞 |

::: 提示 为什么选择 HTTP/2？
尽管HTTP/1.1支持持久连接，但请求必须顺序发送（下一个请求只能在上一个响应返回后发送）。HTTP/2通过复用解决了这个问题，允许同时发送多个请求。
:::

## 2.HTTP 请求的结构

### 2.1 点歌热线

```http
GET /api/users/123 HTTP/1.1
```

包含三部分：
- **方法**：GET、POST、PUT、DELETE 等。
- **URL**：被请求的资源路径
- **版本**：HTTP/1.1 或 HTTP/2

### 2.2 请求头

```http
Host: api.example.com
User-Agent: Mozilla/5.0
Accept: application/json
Authorization: Bearer xxx
Content-Type: application/json
Content-Length: 45
```

常见的请求头：
| 请求头 | 描述 | 示例 |
| :--- | :--- | :--- |
| **Host** | 服务器域名 | `api.example.com` |
| **User-Agent** | 客户端信息 | `Mozilla/5.0` |
| **Accept** | 可接受的响应类型 | `application/json` |
| **Authorization** | 认证信息 | `Bearer token` |
| **Content-Type** | 请求体类型 | `application/json` |

### 2.3 请求体

```json
{
  "name": "Zhang San",
  "email": "zhangsan@example.com"
}
```

只有 POST、PUT、PATCH 及类似方法才有请求体。

## 3. HTTP 响应的结构

### 3.1 状态行

```http
HTTP/1.1 200 OK
```

包含三部分：
- **版本**：HTTP/1.1
- **状态码**：200, 404, 500 等
- **状态文本**：OK, Not Found 等

### 3.2 响应头

```http
Content-Type: application/json
Content-Length: 156
Cache-Control: max-age=3600
Set-Cookie: session=xxx; HttpOnly
```

常见响应头：
| 头部 | 描述 | 示例 |
| :--- | :--- | :--- |
| **Content-Type** | 响应主体类型 | `application/json` |
| **Content-Length** | 响应主体大小 | `156` |
| **Cache-Control** | 缓存策略 | `max-age=3600` |
| **Set-Cookie** | 设置 Cookie | `session=xxx` |

### 3.3 响应体

```json
{
  "code": 0,
  "data": {
    "id": 123,
    "name": "Zhang San"
  }
}
```

## 4.HTTP 方法的详细介绍

|方法 |目的 |请求身体 |幂级 |安全 |
|:--- |:--- |:--- |:--- |:--- |
|**获取** |获取资源 |无 |是 |是 |
|**发帖** |创建资源 |是的 |不 |不 |
|**PUT** |全面更新 |是的 |是的 |不 |
|**补丁** |部分更新 |是的 |不 |不 |
|**删除** |删除资源 |无 |是的 |没有 |
|**头部** |只获取标题 |没有 |是的 |
|**选项** |支持查询的方法 |无 |是的 |是的 |

### 4.1 GET 与 POST

|专题 |获取 |帖子 |
|:--- |:--- |:--- |
|**参数位置** |URL查询参数 |请求正文 |
|**缓存** |可缓存 |默认不缓存 |
|**书签** |可以收藏 |不能 |
|**浏览器历史** |已保存在历史中 |未保存 |
|**数据长度** |有限（URL长度）|无限 |
|**安全性** |URL中可见的参数 |请求正文中的参数 |

::: 提示 什么时候使用GET/POST？
- **GET**：查询，检索数据
- **POST**：创建，提交数据
- **PUT**：全面更新（替换整个资源）
- **PATCH**：部分更新（仅修改指定字段）
- **删除**：删除资源
:::

## 5.HTTP 状态码

### 5.1 状态代码分类

|类别 |描述 |典型状态代码 |
|:--- |:--- |:--- |
|**2xx** |成功 |200 正常，201 创建，204 无内容 |
|**3xx** |重定向 |301 永久，302 临时，304 未修改 |
|**4xx** |客户端错误 |400 错误请求，401 未授权，404 未找到 |
|**5xx** |服务器错误 |500 内部服务器错误，503 服务不可用 |

### 5.2 通用状态代码

|状态代码 |描述 |使用场景 |
|:--- |:--- |:--- |
|**200 OK** |请求成功 |成功 获取，PUT请求 |
|**201 已创建** |资源已创建 |成功发布资源 |
|**204 无内容**无内容 |成功删除 |
|**301 永久迁移** |永久重定向 |URL永久更改 |
|**302 已找到**临时重定向 |URL暂时更改 |
|**304 未修改**未修改 |缓存仍然有效 |
|**400个糟糕请求**糟糕请求 |请求参数错误 |
|**401 未授权**未授权 |需要登录 |
|**403 禁止** |禁止 |已登录但权限不足 |
|**404 未找到**未找到 |资源不存在 |
|**500 内部服务器错误** |内部错误 |服务器异常 |
|**503 服务不可用** |不可用 |服务器维护或过载 |

## 6.HTTPS：安全HTTP

### 6.1 HTTP 与 HTTPS

|功能 |HTTP |HTTPS |
|:--- |:--- |:--- |
|**协议** |TCP |TCP SSL / TLS |
|**港口**80 |443 |
|**数据** |明文 |加密 |
|**证书**非必需 |需要SSL证书 |
|**性能**稍快 |稍慢（握手过头） |
|**SEO** |无影响 |搜索引擎优先考虑 HTTPS |

### 6.2 HTTPS的工作原理

1. **客户端问候**：客户端发送支持的密码套件
2. **服务器问候**：服务器返回证书和所选密码套件
3. **证书验证**：客户端验证服务器证书的有效性
4. **密钥交换**：使用非对称加密交换会话密钥
5. **加密通信**：使用会话密钥进行对称加密

::: 提示 HTTPS 优势
- **反窃听**：数据被加密;第三方无法读取
- **防篡改**：数据完整性验证
- **反冒充**：SSL证书验证服务器身份
:::

## 7. HTTP 缓存机制

### 7.1 缓存头

| 头部 | 描述 | 示例 |
| :--- | :--- | :--- |
| **Cache-Control** | 缓存策略 | `max-age=3600` |
| **ETag** | 资源版本标识 | `"33a64df551425fcc"` |
| **Last-Modified** | 最后修改时间 | `Wed, 21 Oct 2015 07:28:00 GMT` |

### 7.2 缓存策略

**强缓存**：```http
Cache-Control: max-age=3600
```在3600秒内，浏览器直接使用缓存而不发送请求。

**协商缓存**：```http
ETag: "33a64df551425fcc"
```浏览器发送 `If-None-Match`；服务器返回 304（未修改）或 200（已修改）。

## 8. 常见问题

### 8.1 GET 和 POST 的真正区别

**误解**：GET 和 POST 唯一的区别是参数放置的位置。

**事实**：
- GET 是幂等的；多次请求产生相同的结果
- POST 是非幂等的；多次请求可能创建多个资源
- GET 可以被缓存；POST 默认不缓存
- GET 可以被收藏；POST 不可

### 8.2 HTTP/1.1 队头阻塞

**问题**：虽然 HTTP/1.1 支持持久连接，但请求必须按顺序发送。如果前一个请求的响应很慢，所有后续请求都必须等待。

**解决方案**：
- HTTP/2 多路复用
- 域名分片（多个域名用于多个连接）
- 连接池（限制并发）

### 8.3 HTTP/2 优势

| 功能 | HTTP/1.1 | HTTP/2 |
| :--- | :--- | :--- |
| **传输格式** | 文本 | 二进制帧 |
| **多路复用** | 不支持 | 支持 |
| **头部压缩** | 无 | HPACK 算法 |
| **服务器推送** | 不支持 | 支持 |
