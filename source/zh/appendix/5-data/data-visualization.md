# 数据可视化原则

::: tip 前言
**一张好的图表胜过千行数据。** 数据可视化将抽象的数字转化为直观的视觉呈现，使人们能够在几秒钟内理解数据背后的故事。从 Excel 图表到 Grafana 监控仪表盘，视觉化无处不在。
:::

## 0. 全局视角：为什么可视化重要

人脑处理视觉信息的速度远快于文本信息。折线图可以让你快速看到“上个月销售下滑”，而相同信息如果以表格呈现，可能需要逐行对比才能得出相同结论。

可视化的核心价值：

- **发现模式**：趋势、周期和异常点在图表中立刻可见
- **支持决策**：让非技术人员理解数据并参与决策
- **提高沟通效率**：一图胜千言，减少数据解读的歧义

::: tip 可视化 ≠ 美观
可视化的目标是**传递信息**，而不是炫耀。一个简洁但准确的柱状图比一个炫丽但难以理解的 3D 图表更有价值。
:::

## 1. 图表类型选择：用合适的图讲合适的故事

选择图表的第一步不是“我喜欢什么图表”，而是“我想传达什么信息”。不同的数据目的对应不同的最优图表类型。

<ChartTypeSelectorDemo />

### 图表选择快速参考

| 数据目的 | 推荐图表 | 不推荐 | 原因 |
|---------|---------|--------|------|
| 比较大小 | 条形图、柱状图 | 饼图 | 人眼对长度差异比角度差异更敏感 |
| 展示趋势 | 折线图、面积图 | 柱状图 | 折线的连续性暗示时间连续性 |
| 展示比例 | 饼图（≤5类）、堆叠柱状图 | 3D 饼图 | 3D 视角会扭曲面积比例 |
| 展示分布 | 直方图、箱线图 | 折线图 | 分布关注频次，而非趋势 |
| 展示关系 | 散点图、气泡图 | 柱状图 | 两个连续变量的关系需要二维空间 |

::: 提示 一个简单的决策规则
- **一个变量** → 直方图（分布）或数字卡片（关键绩效指标，KPI）
- **两个变量** → 折线图（时间 vs 值）或散点图（值 vs 值）
- **多类别** → 条形图（比较）或饼图（比例，≤5 类别）
- **多维度** → 雷达图或平行坐标图
:::

## 2. 可视化设计原则：视觉编码原则

好的可视化不是为了“美观”，而是为了“易懂”。Edward Tufte 在《定量信息的视觉展示》中提出的几个经典原则，如今仍是可视化设计的重要参考。

| 原则 | 描述 | 反模式 |
|------|------|---------|
| 数据墨水比 | 图表中用于展示数据的“墨水”比例应尽可能高 | 过多的网格线、装饰性元素 |
| 最小化非数据元素 | 移除不传达信息的视觉元素 | 3D 效果、阴影、渐变背景 |
| 尺度一致性 | 轴从零开始，刻度统一；如果截断轴，应明确标示 | Y 轴从 95 开始但没有说明 |
| 颜色使用合理 | 使用颜色编码信息，而不是装饰 | 顺序数据使用彩虹色 |
| 标签清晰 | 标题、坐标轴标签、图例及单位缺一不可 | 没有单位，没有时间范围 |

### 2.1 数据墨水比

> 图表中用于表达数据的“墨水”相对于总墨水的比例应尽可能高。

简单来说：**删除所有不传递信息的内容**。

| 应删除 | 应保留 |
|-----------|-----------|
| 3D 效果、阴影、渐变 | 数据点、轴标签 |
| 过多网格线 | 关键参考线（例如目标值） |
| 装饰性图标 | 图例（当有多个系列时） |
| 花哨的背景色 | 清晰的标题和单位 |

### 2.2 一致性原则

- **颜色一致**：在不同图表中同一维度使用相同颜色，例如“收入”始终为蓝色
- **尺度一致**：尽可能让轴从 0 开始，除非有充分理由并明确标注
- **时间一致**：时间轴的间隔应均匀；不要将不均匀的时间点当作均匀间隔绘制

### 2.3 可读性原则

- **标题应表述结论**：不写“月度销售”，而写“销售连续三个月下降”
- **标注关键点**：在异常值和拐点处添加注释，引导读者关注
- **控制信息密度**：每个图表应传达 1-2 个核心信息；不要堆砌过多内容

::: 提示 颜色使用三原则
1. **相同指标，相同颜色**：收入在所有图表中应始终为蓝色，而不是有时蓝色、有时绿色
2. **顺序数据用渐变**：温度从低到高使用蓝→红渐变，而不是离散颜色
3. **考虑色盲友好**：约 8% 男性有红绿色盲；避免仅依赖红色和绿色区分重要信息
:::

## 3. 仪表板布局：不同场景，不同模式

仪表板是多图表的有机组合。一个好的仪表板不仅仅是堆叠图表，而是根据使用场景选择合适的布局模式。

<DashboardLayoutDemo />

### 四种常见布局模式

|布局模式 |核心结构 |用例 |设计要点 |
|---------|---------|---------|---------|
|概述 |KPI卡趋势图详细表格 |高管每日报告、运营仪表盘 |将核心指标置于顶部;关键数字一目了然 |
|比较分析 |对称左右布局 |A/B 测试，年比分析 |保持比较维度一致，突出差异 |
|深入分析 |从摘要到细节的渐进扩展 |销售分析，用户行为分析 |支持点击交互，层层探索 |
|实时监控 |大数字实时曲线警报状态 |双十一大屏幕，服务器监控 |自动刷新，暗背景，适合投影 |

### 5 仪表盘设计原则

1. **首先问“谁在看”**：CEO查看战略指标，运营查看流程指标，工程师查看技术指标
2. **5秒规则**：用户应在5秒内理解仪表盘的核心信息
3. **信息层级**：将最重要的内容置于左上角，次要内容置于下方
4. **减少滚动**：将核心内容展示在一个屏幕上;避免让用户滚动查看关键数据
5. **留白**：不要填满每一寸空间;适当的留白能让视觉体验更舒适

::: 提示 仪表盘 vs. 报告
- **仪表盘**：实时/近实时，互动，注重监控和快速决策
- **报告**：定期生成（每日/每周/每月），静态，注重详细分析和归档

这两者不是彼此的替代，而是互补。仪表盘识别问题;报告深入分析。
:::

## 4.工具选择：从代码库到商业智能平台

可视化工具可分为三层：代码级图表库、数据分析图表库和商业智能平台。选择哪一类取决于需求复杂度、交互需求和团队技术能力。

### 4.1 代码级图表库

|工具 |语言/平台 |功能 |使用场景 |
|------|----------|------|---------|
|ECharts |JavaScript |即用，丰富的图表类型，优秀的文档 |业务系统中的嵌入图表 |
|D3.js |JavaScript |低层次灵活性，可自定义任何可视化 |高度定制化的数据可视化 |
|Chart.js |JavaScript |轻量级、简洁、快速上手 |简单的图表需求 |
|Matplotlib |Python |标准科学计算库，静态图表 |数据分析，纸质图表 |
|Plotly |Python/JS |交互式图表，3D 支持 |数据探索，Jupyter Notebook |

### 4.2 BI平台（无代码/低代码）

|工具 |站位 |核心力量 |合适团队 |
|------|------|---------|---------|
|Grafana |监控可视化 |强力的时间序列支持，警报集成 |运维/SRE团队 |
|Metabase |轻量级BI |开源且免费，利用SQL创建图表 |中小型团队快速构建 |
|Apache 超集 |企业BI |开源，支持大数据源 |拥有数据团队的公司 |
|Tableau |商业BI |拖放，出色的可视化 |商业分析师 |
|Power BI |商业BI |与 Microsoft 生态系统的强力集成 |企业使用 Microsoft 技术栈 |

::: 小贴士 选择建议
- **开发者在产品中嵌入图表** → ECharts 或 Chart.js（针对简单场景）
- **进行探索性分析的数据分析师** → Plotly Jupyter 或 Metabase
- **运营监控仪表盘** → Grafana（事实上的标准）
- **进行自助分析的业务团队**→Metabase（开源）或Tableau（商业版）
- **需要高度定制** → D3.js（学习曲线陡峭，但极具灵活性）
:::

## 5.常见陷阱：这些图表在欺骗你

数据可视化是一把双刃剑：用得好，能揭示真相;用得不当，则制造错觉。以下是每位数据从业者都应当识别的最常见可视化陷阱。

### 5.1 截断斧头

将Y轴起始点从0改为大，会让微小的差异看起来像巨大的变化。

|情景 |实际差异 |视觉感知 |
|------|---------|---------|
|纵轴从0开始 |乘积A：98点，乘积B：95点 |小间隙 |
|纵轴从90 |相同的数据 |A 似乎比 B 大几倍 |

**何时截断是可接受的？** 当绝对值较大但变化较小（例如股价从100到105）时，截断是合理的，但必须明确标注。

### 5.2 三维圆饼图透视陷阱

三维透视让靠近观察者的扇区看起来更大。25%的扇区在3D视角下看起来可能像35%。

**解决方案**：绝不要使用3D饼图。使用普通饼图或甜甜圈图，或者干脆使用柱状图。

### 5.3 色彩滥用

|错误的做法 |正确的做法 |
|---------|---------|
|使用红绿色表示数据 |使用蓝橙色及其他色盲安全调色板 |
|每个类别的不同颜色 |同一系列使用同一色系的色调 |
|用颜色编码连续数据但无图例 |始终提供颜色图例和值标签 |
|背景色与数据色对比度不足 |确保WCAG AA级对比度 |

### 5.4 其他常见错误

|陷阱 |问题 |修复 |
|------|------|------|
|双Y轴 |两个无关的度量共享X轴意味着因果关系 |拆分为两个图表，或明确说明无因果关系|
|面积误表示 |用圆的半径代替面积来表示数值 |当值加倍时，面积应当加倍，而不是半径 |
|时间轴不均 |一月、三月和十二月间隔均匀 |按实际时间比例排列 |
|类别过多 |包含15个扇区的饼图 |超过5个类别使用条形图，或归入“其他” |

::: 提示 可视化伦理指南
可视化的目的是**帮助理解**，而不是**操控感知**。每次制作图表时，请问自己：

- 如果我是读者，这张图表会让我得出错误结论吗？
- 我是在隐瞒不利数据吗？
- 轴、比例和颜色是否公平地呈现数据？
:::

## 摘要

数据可视化是传递数据价值的“最后一公里”。无论分析多么优秀，如果无法正确理解，就等同于分析从未发生过。

让我们回顾一下本章的主要要点：

1. **选择合适的图表**：根据数据目的（比较、趋势、比例、分布、关系）选择图表类型
2. **设计原则**：高数据墨水比、一致性和可读性是三个核心原则
3. **仪表板布局**：概览、比较、深入分析和实时模式覆盖大多数场景
4. **工具选择**：从 ECharts 到 Grafana，根据团队能力和需求复杂性选择
5. **避免陷阱**：截断坐标轴、三维饼图和颜色误用是最常见的误导手法
