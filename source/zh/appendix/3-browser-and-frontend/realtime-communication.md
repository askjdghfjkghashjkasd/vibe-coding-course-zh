# 实时通信原理：轮询、SSE 与 WebSocket

::: tip 核心阅读指南
**浏览器如何实现实时数据更新？**  
传统的 HTTP 协议基于“请求-响应”模型，客户端必须主动发起请求，服务器才能返回数据。如果我们需要实现聊天室或股市行情等实时场景，这种模型将面临很大的挑战。

本章介绍前端用于实时数据通信的三种主要技术：短轮询、服务器发送事件（SSE）以及全双工 WebSocket，并探索它们的原理和适用场景。
:::

---

## 1. 传统 HTTP 的局限性

HTTP 协议最初是为文档获取设计的，具有**无状态**和**由客户端单向发起**的特性：  
1. 客户端发起 HTTP 请求。  
2. 服务器处理请求并返回响应。  
3. 任务完成后，连接通常会释放（尽管 HTTP/1.1 支持持久连接复用，但业务层的请求-响应模型保持不变）。

在这种模型下，服务器无法随时主动通知等待的客户端状态变更。要获取最新数据，必须寻找其他技术架构方案。

---

## 2. 短轮询

最直接的解决方案是**短轮询**。客户端利用计时器（例如 `setInterval`）以固定时间间隔自动发送 HTTP 请求到服务器，询问是否有新数据到达。

<PollingDemo />

**技术特性与局限性：**  
- **优点**：实现机制极其简单，完全依赖标准 HTTP 协议和 AJAX/Fetch 技术。  
- **缺点**：可能产生大量网络开销和资源浪费。大部分时间服务器的响应可能是“无新数据”。无论是否有数据，每次请求都必须携带完整的 HTTP 头信息（Headers、Cookies 等）。在高并发场景下，网络资源可能被大量无意义的查询占用。

---

## 3. 服务器发送事件（SSE）

为了减少频繁建立 HTTP 连接的开销，**服务器发送事件（SSE）** 提供了一种轻量级的单向数据流推送架构。

SSE 构建在 HTTP 协议之上。客户端使用带有特殊头信息的 HTTP 请求 (`Accept: text/event-stream`) 发起请求后，服务器在返回响应时保持底层 TCP 连接打开。随后，服务器可以通过这个持久连接持续向客户端推送文本格式的数据。

<SSEDemo />

**技术特性与局限性：**  
- **优点**：持久连接，网络开销低；浏览器原生支持断线自动重连；非常适合服务器到客户端的**单向**流式数据传输（例如大型语言模型文本逐 token 输出、实时交易行情）。  
- **缺点**：通信通道是单向的。如果客户端需要向服务器发送控制命令或新数据，必须建立单独的普通 HTTP 请求。

---

## 4. WebSocket：全双工通信协议

当应用场景涉及高频双向交互（如多人在线动作游戏、精准协作文档编辑）时，我们需要一种既能降低通信开销又实现真正双工通信的技术——**WebSocket**。

WebSocket 是一种独立的网络通信协议。它优雅地利用 HTTP 协议完成初始连接：
1. **握手阶段**：客户端发送一个特殊的HTTP请求，声明升级到新协议的意图（带有`Upgrade: websocket`头部）。
2. **连接转换**：如果服务器支持并同意该协议，会以 `101 Switching Protocols` 状态码响应。
3. **完全自由**：此时，HTTP的规范任务结束，底层的TCP连接交由WebSocket协议管理。此后，客户端和服务器享有同等的全双工通信权利，双方可随时发送和接收最小格式数据帧。

<WebSocket演示 />

**技术特性与局限性：**
- **优势**：支持真正的双向实时通信;数据帧头极小，通信延迟低且吞吐量高;支持本地二进制数据（ArrayBuffer）传输。
- **缺点**：更高的架构和开发复杂度;由于保持持久的长时间连接，服务器端系统架构、负载均衡策略和心跳监测设计对工程要求更严格。

---

## 5.摘要：技术选择比较

|维度 |短轮询 |服务器发送事件（SSE） |WebSocket |
|:--- |:--- |:--- |:--- |
|**通信方向**客户端主动轮询和拉取（单向）|服务器持续主动推送（单向）|客户端和服务器拥有平等的发送/接收权（双向全双工）|
|**底层协议** |标准HTTP |标准HTTP |独立WebSocket协议（基于TCP）|
|**数据开销** |极高（包含完整HTTP头）|低 |极低（最小数据帧头）|
|**典型用例** |定期检查后端异步任务的完成状态 |LLM对话单向流输出、新闻或系统通知推送 |实时音频/视频信令、多人在线游戏、协作白板和编辑 |

在实际工程中，开发者应根据具体业务场景对实时性能和双向交互频率的需求，平衡系统维护复杂性和通信效率，选择最合适的技术栈。
