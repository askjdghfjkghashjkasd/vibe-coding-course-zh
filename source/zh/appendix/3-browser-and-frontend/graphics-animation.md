# 图形和动画基础：Canvas 及相关技术

::: tip 核心问题

早期网页只能显示纯文本和图片。但是，如果你想制作一款打砖块游戏、华丽的动态效果，或者一个自由拖拽的数据报表，仅仅依靠 `<div>` 是远远不够的。这就是**Canvas**诞生的原因。

本指南将带你从绘制第一条直线，一直到构建一个在浏览器中流畅运行 60 FPS 的粒子引擎。

:::

## 1. Canvas 概览

如果早期网页是由 **乐高积木**（HTML 标签）组合而成的静态模型，那么 HTML5 的 `<canvas>` 标签就像给你提供了一个 **巨大的数字画布**，以及一个由代码控制的 **画笔**，其余的则交给你的创意自由。

这里的绘图中没有标签结构。一旦用画笔画了什么，它立即变成纯粹的 **“像素颜料”**。

### 1.1 Canvas vs SVG：两种不同画家流派

在前端绘图领域，Canvas 有一个竞争对手叫 **SVG**。它们代表了两种完全不同的绘图方法：

- **Canvas（位图画板）：**
  - **原理**：就像在真实纸张上作画——几笔就变成了一块颜料（像素）。
  - **优点**：计算机只需“泼漆”到屏幕上——性能飞快！可以同时渲染成千上万的弹跳闪烁粒子。
  - **缺点**：绘制后无法单独取消（无法通过 DOM 节点选择），放大看会出现马赛克模糊。
- **SVG（矢量图形拼装）：**
  - **原理**：就像制作 PPT 讲义。你画一个圆，它会在画布上生成一个独立的“圆形实体”标签。
  - **优点**：无论放大 100 倍或 10 万倍，总是清晰锐利。每个形状都是独立 DOM 节点——可以随时用 CSS 和 JS 改变颜色或绑定点击事件。
  - **缺点**：如果尝试让上万对象同时移动，庞大的 DOM 树和布局引擎会让浏览器卡顿。

**简单总结：动态游戏和炫酷粒子效果用 Canvas；精确的 Logo 和交互图表用 SVG。**

## 2. 第一笔：理解颠倒的坐标系

### 2.1 倒置画布的动机

当你准备开始绘图时，首先需要明白 Canvas 中的标尺是倒置的。在传统数学课堂坐标系中，零点在中心，数值向上增大。但在计算机屏幕显示中，几乎所有设备都将 **“原点 (0, 0)”定在屏幕左上角**。向右移动 X 轴数值增加——这没有问题——但 **向下移动 Y 轴数值增加**。

**Canvas 坐标系核心原则：**
- **原生单位**：像素（px），与屏幕物理像素 1:1 对应。
- **X 轴**：正方向向右，从 `0` 到 `canvas.width`。
- **Y 轴**：正方向向下，从 `0` 到 `canvas.height`。

### 2.2 调制你的魔法画笔

在确定坐标系之后，我们可以召唤画笔（称为 `Context`，在代码中简称 `ctx`）。就像用真实调色板作画一样，Canvas API 的设计完美遵循物理绘画的三个步骤：

1. **颜色混合（状态）**：填充颜色用`fillStyle`，笔画颜色用`strokeStyle`。
2. **塑形（路径）**：决定你想画一条线（`lineTo`）、圆（`arc`）还是矩形（`rect`）。
3. **最小笔触（渲染）**：决定是填充内部（`fill()`）还是勾勒边缘（`stroke()`）。

由于Canvas是一个纯位图画布，画完后“无遗憾”，一旦你作画，它会立即变成像素，无法作为独立对象被撤销。

## 3.翻页动画：如何让图形流畅流畅

既然Canvas一旦填满就会变成永久像素，那么HTML5游戏中那些在屏幕上奔跑的角色是如何生成的？

答案是**“欺骗你的眼睛”。** 这完全像翻页书或电影胶片一样。

1. **清除板块（清空）**：使用`clearRect()`无情地清除整幅画布。
2. **计算新位置（更新）**：偷偷在角色的X坐标上添加2个像素。
3. **重绘（渲染）**：将角色绘制到新位置。
4. **疯狂循环*：与浏览器内置的精确节拍器 `requestAnimationFrame` 结合。它以显示器刷新率（通常为每秒60次，即60 FPS）重复这三个动作。

由于人眼的“视觉持久性”，在每秒60个循环的[擦除 -> 更新 ->重绘]中，你看到的不是闪烁的黑板，而是像丝绸般流畅的动画。

## 4.盲人的虚张声势：在Canvas中处理点击交互的方法

因为浏览器把画布看作是没有结构的“颜料布”。假设你画了一个带有`arc()`的怪物，想实现“点击怪物造成伤害”——你**根本不能**用传统的`document.getElementById`来画这个怪物。因为在HTML结构中，只有那个刚性标签，宽度为600像素。

这是图形编程中最经典的问题：**碰撞检测与事件委派**。

由于浏览器只知道你的鼠标点击了Canvas屏幕坐标`(x, y)`，你需要用中学几何来反向计算：
- **对于圆**：使用毕达哥拉斯定理计算 `mouse click point` 到 `circle center position` 的距离。如果距离小于半径，则称为“击中”。
- **对于矩形**：检查点击的`x`是否位于矩形的左右边界内，同时检查`y`是否在上下边界内。

无论画布上有多少元素，鼠标悬停或点击事件始终绑定在画布上，作为唯一的容器——这就是终极的“事件委托”。

## 5.解放计算能力：粒子系统与视觉魔法

此时，当我们将“坐标系”、“动画循环”和“颜色与形状”结合起来，并将其数量乘以数百甚至数千个微小碎片时，你已经掌握了终极视觉武器：**粒子系统**。

它的核心方法非常简单但有效：
1. 创建一个包含数百个独立“粒子对象”的巨大数组。
2. 每个对象都有自己的生命周期（`life`）、速度（`vx/vy`）和重力阻尼（`gravity`）。
3. 每次 `requestAnimationFrame` 触发时，遍历并更新这些数百个粒子，渲染它们，并静默清理那些“死亡”的粒子（生命周期耗尽或掉出屏幕）。

你的浏览器瞬间可以变成一个生产烟花、暴风雪和爆炸的梦工厂。

## 6. 守护 FPS 荣耀：处理 CPU 过热的方法

让数千个对象每秒计算和重绘 60 次对性能要求极高。如果没有适当的技巧，你的电脑风扇很快就要起飞了。

以下是真正的引擎专家用来拯救帧率的“保镖技巧”：

1. **部分擦除（脏矩形）：**
   当一个角色跑过广阔的草地时，绝不要每帧 `clearRect` 整个草地！只在角色经过的特定小区域使用“小橡皮擦”进行重绘——性能马上会呈指数级飞升。

2. **幕后替身（离屏画布）：**
   如果背景是复杂的星空和精美的山脉，每次实时渲染是愚蠢的。我们通常会在内存中秘密创建一个不可见 `<canvas>`，并将美丽的背景绘制到上面一次。在随后的帧刷新中，我们只是使用 `drawImage()` 将这个合成的“静态底图”直接粘贴，消除了大量基础计算。

3. **批量画刷洗涤（批处理）：**
   在低层切换从红色到蓝色的画笔代价很高。如果画布上有 1,000 个红色圆圈和 1,000 个蓝色圆圈交替分布，最快的方法是：先准备红色画笔，遍历并绘制所有红色圆圈，然后切换到蓝色画笔绘制所有蓝色圆圈。这就是著名的批量渲染概念。

## 7. 术语总结

| 术语 | 直白解释 |
| --- | --- |
| **Canvas** | HTML5 提供的二维画布。渲染速度极快，但一旦绘制完成，所有内容都变成像素颜料——DOM 操作无法修改画布内容。 |
| **SVG** | 矢量图形。放大时永不模糊，每个形状都是独立的标签元素，能够轻松绑定 CSS 样式和交互。 |
| **Context (ctx)** | 你请求的“二维魔法画笔”，用于混合颜色、定义形状以及渲染各种特殊效果。 |
| **requestAnimationFrame** | 浏览器内置的顶级节拍器，严格按照显示器刷新率执行回调——创建丝滑动画的终极选择。 |
| **FPS (帧率)** | 每秒帧数。60 FPS 意味着浏览器每秒无缝擦除并重绘画布 60 次。 |
| **Dirty Rectangle** | 精确地仅在变化的微小区域内擦除并重绘，从而大幅提升性能。 |
| **Offscreen Canvas** | 内存中隐藏的“影子画布”。预绘制极其复杂但静态的场景，然后将其作为死纹理重复使用。 |

> 从简单的直线段到宏伟的粒子系统引擎——所有看似魔法的效果，不过是每秒 60 次坐标计算和重绘循环而已。
