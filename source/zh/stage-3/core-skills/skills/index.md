# Claude Code 技能完整指南

## 技能简介

**Claude Code 技能** 是一种将专业知识、工作流程和最佳实践打包成可重用“技能包”的功能。

你可以把技能想象成为 Claude 准备好的“技能书”。当你需要它完成特定任务时，你不必一次又一次地解释需求。相反，它可以直接按照技能预先定义的标准来执行工作。

### 为什么我们需要技能？

在技能出现之前，使用 Claude Code 有几个问题：

- **重复说明**：每次都必须解释“遵循什么编码风格”以及“提交信息应如何书写”等内容
- **知识无法积累**：团队成员使用 Claude 的个人经验无法共享
- **标准不一致**：不同人的使用可能得到完全不同的结果
- **效率低下**：常见任务每次都必须从头说明

技能解决了这些问题，使 Claude 成为“经验丰富的团队成员”——它了解你的项目规范、工作流程和最佳实践。

### 第 1 步：安装 `find-skills`（强烈推荐）

在开始使用技能之前，强烈建议你先安装 `find-skills`。它是 AI 智能体 世界中的“终极技能搜索工具”，目前已有 6 万订阅。

**`find-skills` 是什么？**

简单来说，`find-skills` 就像 AI 智能体 的“应用商店搜索引擎”。当你需要完成某个任务却没有合适的本地技能时，它会自动搜索并推荐最合适的技能。

**安装 `find-skills`：**

```bash
npx skills add vercel-labs/skills@find-skills -g -y
```

安装后，您可以直接告诉Claude您的需求，它会自动使用`find-skills`搜索相关技能。

**使用示例：**

```text
I need to optimize the performance of a React component. Help me find what skills I can use.
```

Claude 将搜索 `find-skills`，然后告诉你它找到的相关技能，以便你选择一个进行安装。

**为什么要先安装 `find-skills`？**

在 `find-skills` 之前：
- 手动在 GitHub 上搜索相关技能
- 一一复制、安装并配置它们
- 反复调试和适配它们

在 `find-skills` 之后：

- AI 自动搜索最匹配的技能
- 一键安装并立即使用

### 第三个技能：使用 `frontend-slides` 快速制作精美的PPT演示文稿

#### 介绍

**frontend-slides** 是一个技能，允许你通过自然语言创建漂亮的HTML演示文稿——即使你不懂任何CSS或JavaScript。

它的核心理念是“**以展示为主，而非描述**”。如果你无法清晰描述你想要的设计风格，它将为你生成3个视觉预览供你选择，而不是强迫你去描述抽象的要求，如“蓝色背景，大字体”。

#### 安装 `frontend-slides`

**方法1：手动安装**

```bash
# Create the skill directory
mkdir -p ~/.claude/skills/frontend-slides

# Download files (or copy from GitHub)
# 1. Visit https://github.com/zarazhangrui/frontend-slides
# 2. Download SKILL.md and STYLE_PRESETS.md
# 3. Put them into ~/.claude/skills/frontend-slides/
```

**方法2：使用`find-skills`安装**

```text
Help me find a skill for making PPT presentations
```

Claude 将搜索 `find-skills` 并推荐 `frontend-slides`。

#### 使用场景

**场景 1：从零创建演示文稿**

```text
/frontend-slides

I want to create a fundraising pitch deck for an AI startup project, around 10 slides
```

Claude 将引导您：
1. 填写每张幻灯片的内容，例如标题、要点和图片
2. 描述您想要的感觉，例如惊艳、专业或温暖
3. 从 3 个视觉风格预览中进行选择
4. 创建完整的 HTML 演示文稿
5. 在浏览器中打开预览

**场景 2：转换 PowerPoint 文件**

```text

Claude 将会：

2. 展示提取的内容供你确认

4. 生成一个保留所有原始内容的 HTML 演示文稿

## 技能是什么？

### 核心概念

**技能是存储在文件系统中的“技能包”**，可以包括：

- **SKILL.md**：技能定义文件，必需
- **scripts/**：辅助脚本，可选
- **templates/**：输出模板，可选
- **references/**：参考文档，可选

### 技能与提示的区别

你可能想知道：技能与直接向 Claude 发送提示有什么不同？

| 提示 | 技能 |
|--------|--------|
| 临时的，每次都要重复 | 持久的，编写一次，可复用多次 |
| 存在于对话历史中并消耗令牌 | 按需加载并节省令牌 |
| 不能跨会话共享 | 可以在团队内共享 |
| 难以进行版本控制 | 可以通过 Git 管理 |

### 两种类型的技能

**全局技能（个人）**：
- 存储位置：`~/.claude/skills/`
- 范围：所有项目
- 适用场景：通用个人技能

**项目技能（团队）**：
- 存储位置：`project-directory/.claude/skills/`
- 范围：当前项目
- 适用场景：团队共享和项目特定约定

### 技能的工作原理

当 Claude Code 启动时，它将：

1. 扫描技能目录
2. 解析每个 `SKILL.md` 文件
3. 提取 YAML 前置元数据
4. 将技能内容添加到其“知识库”中
5. 根据描述自动匹配触发器

## `SKILL.md` 文件结构

### 基本结构

完整的技能目录如下所示：

```text
my-skill/
├── SKILL.md          # Required: skill definition file
├── scripts/          # Optional: helper scripts
├── templates/        # Optional: output templates
├── references/       # Optional: reference documents
└── examples/         # Optional: example files
```

### `SKILL.md` 模板

`SKILL.md` 文件有两部分：

**部分 1：YAML 前置信息（元数据）**

```yaml
---
name: skill-name              # Skill name, becomes the /skill-name command
description: short description # Used for Claude's automatic trigger matching
category: development         # Category
tags:                         # Tags
  - code
  - automation
---
```

**第2部分：Markdown 内容（说明）**

```markdown
# Skill Title

## Use cases
When to use this skill

## Execution steps
1. Step one
2. Step two

## Notes
- Note 1
- Note 2
```

### 关键字段说明

| 字段 | 是否必填 | 说明 |
|------|------|------|
| `name` | 是 | 技能名称。只允许使用小写字母、数字和连字符 |
| `description` | 是 | 技能描述。描述越具体，Claude 自动匹配越容易 |
| `category` | 否 | 分类标签 |
| `tags` | 否 | 其他分类标签 |
| `allowed-tools` | 否 | 可以在无需额外许可的情况下使用的工具 |

## 技能 vs. MCP：区别是什么？

许多初学者容易将技能和 MCP 混淆，但它们完全不同。

### 核心区别

| 维度 | 技能 | MCP |
|------|--------|-----|
| **本质** | 知识和工作流程 | 工具和接口 |
| **提供内容** | 告诉 AI "如何做" | 给 AI "可以使用什么" |
| **存储位置** | `skills/` 目录 | MCP 服务器 |
| **配置格式** | Markdown 文件 | JSON 配置文件 |
| **触发方式** | `/skill-name` 或自动识别 | 通过配置自动加载 |

### 一个直观的比喻

如果 Claude 是一个“工人”：

- **MCP** 就是给工人的“工具”，如扳手、电脑和访问权限
- **技能** 就是给工人的“操作手册”，例如如何进行代码审查或提交代码

### 它们的关系

技能和 MCP 并不是相互竞争的。它们是互补的：

```text
User task -> Claude recognizes the requirement
               ↓
        Load relevant Skills (know how to do it)
               ↓
        Call tools through MCP (have tools available)
               ↓
        Complete the task
```

### 示例

**场景：代码审查**

- **Skills（技能）** 定义审查步骤、检查清单和输出格式
- **MCP** 提供访问 GitHub PR 并获取代码差异的能力

协作方式：Skills 告诉 Claude “如何审查”，而 MCP 给 Claude “访问代码的能力”。

### 选择建议

| 您的需求 | 推荐方案 |
|----------|----------|
| 需要定义工作流程 | 使用 Skills |
| 需要访问外部数据 | 使用 MCP |
| 两者都需要 | 一起使用 |

## 如何创建你自己的技能

创建技能有两种方式：直接让 Claude 为你创建，或使用专用的 `skill-creator` 工具。

### 方法 1：直接请 Claude 帮你创建

这是最简单的方法。只需用自然语言告诉 Claude 你的需求即可。

**示例**:

```text
Please help me create a skill named "format-code" to automatically format code.

Requirements:
1. Automatically detect the programming language
2. Apply the corresponding formatting rules
3. Return the diff before and after formatting
```

Claude 将自动执行以下操作：
1. 创建目录结构
2. 生成 `SKILL.md` 文件
3. 填写 YAML 前置信息
4. 编写技能内容

**适用场景**：
- 快速创建简单技能
- 你知道自己想要什么，但不熟悉 `SKILL.md` 格式
- 你希望快速迭代和修改

### 方法 2：使用 `skill-creator`

`skill-creator` 是用于创建技能的专用工具。它会一步步引导你完成整个过程。

**安装**：

```bash
npx skills add anthropics/skills@skill-creator -g
```

或者安装整个官方技能库：

```bash
npx skills add anthropics/skills -g
```

**使用**：

```text
/skill-creator
```

然后填写提示内容：
- 技能名称
- 功能描述
- 使用场景
- 执行步骤

`skill-creator` 将会：
1. 指导你明确技能的目的
2. 生成 `SKILL.md` 草稿
3. 创建测试用例
4. 运行评估并优化

**适用场景**：
- 创建复杂技能
- 需要更标准的创建流程
- 想要测试和验证技能

### 两种方法的比较

| 方法 1：直接创建 | 方法 2：`skill-creator` |
|-----------------|---------------------|
| 快速且简单 | 分步指导 |
| 适合简单技能 | 适合复杂技能 |
| 在对话中直接完成 | 标准化流程 |
| 灵活修改 | 包括测试和验证 |

## 常见问题

### 问题1：为什么技能没有被触发？

可能原因：
- YAML frontmatter 格式错误
- 描述不够具体
- Claude Code 未重启

解决方法：
- 检查 YAML 格式是否正确
- 改进描述，并包含具体的使用场景
- 重启 Claude Code

### 问题2：如何写出准确的描述？

好的描述包括：
- 技能的具体功能
- 使用场景，例如“当用户提到……时”
- 触发关键词

**错误示例**：```text
description: Review code
```

**好例子**：```text
description: Review Pull Request code. Trigger when the user mentions PR, review, or code review.
```

### Q3：技能和指令有什么区别？

|指令 |技能 |
|----------|--------|
|简单的快捷指令 |完整的工作流程 |
|一个 `.md` 文件 |一个目录结构（`SKILL.md` 可选文件） |
|手动触发 |可以自动触发 |
|适合简单操作 |适合复杂过程 |

### Q4：我该如何调试一个技能？

1. 使用 `/skills` 检查该技能是否被认可
2. 直接输入技能名称以手动触发
3. 检查`SKILL.md`的内容是否正确
4. 审查Claude代码日志

## 延伸阅读：克劳德技能的内部机制

接下来，我们将更深入地探讨 Claude Skills 的内部运作方式，让你不仅知道如何使用它们，还能理解它们为何被这样设计。

### 从第一性原理的角度看：基于提示的动态上下文注入

首先，要理解一个关键事实：**技能不是可执行代码**。

技能本质上是高级指令或提示，在需要时会被“注入”到Claude的上下文中。这种设计称为“**基于提示的动态上下文注入与元工具架构**”。

```text
┌─────────────┐      ┌─────────────┐      ┌──────────────┐
│ User Request│ ───> │ LLM Matches │ ───> │ Trigger Skill│
└─────────────┘      │Description  │      └──────────────┘
                     └─────────────┘              │
                                                 ▼
                                          ┌──────────────┐
                                          │ Inject Full  │
                                          │ Instructions │
                                          └──────────────┘
                                                 │
                                                 ▼
                                          ┌──────────────┐
                                          │ Execute Task │
                                          └──────────────┘
```

### 三层渐进加载架构（令牌优化）

为了在不消耗大量令牌的情况下处理大量技能，Claude 使用了一种智能的三层加载机制：

| 层级 | 内容 | 加载时间 | 令牌消耗 |
|------|------|----------|-----------|
| **第一层：元数据** | YAML frontmatter (`name + description`) | Claude 启动时 | 每个技能约 30-50 个令牌 |
| **第二层：指令** | 完整 `SKILL.md` 内容 | 当技能被触发时 | 约 5,000 个令牌 |
| **第三层：资源** | 脚本、模板、参考文档 | 根据需要从文件系统访问 | 不计入上下文 |

**此设计的优势**：

- 假设你有 100 个技能，启动时仅为元数据消耗约 3,000-5,000 个令牌
- 只有被触发的技能会加载其完整内容
- 诸如参考文档的资源文件从不完全加载到上下文中

**与没有技能相比：**

```text
Without Skills: every conversation needs 50,000+ tokens to describe all capabilities
With Skills: startup ~100 tokens/skill + 5,000 tokens loaded on demand
Savings: on average 40,000+ tokens saved per conversation
```

### 双重上下文注入机制

当一个技能被激活时，系统会同时进行两项修改：

**1. 对话上下文注入**

```javascript
// What the user sees (visible message)
<command-message>The "pdf" skill is loading</command-message>

// What the AI actually receives (hidden meta-message)
{
  isMeta: true,  // marked as a meta-message, not shown in the UI
  content: `
    # PDF Analysis Expert Instructions

    You are a professional PDF analysis expert. Workflow:
    1. Use pdftotext to extract text
    2. Analyze the document structure
    3. Generate a summary report
    ...
  `  // full SKILL.md content, possibly thousands of words
}
```

**2. 执行上下文修改**

除了注入指令外，技能还可以动态修改 Claude 的环境：

| 修改类型 | 示例 | 说明 |
|---------|------|------|
| **工具权限** | `allowed-tools: "Bash(pdftotext:*)"` | 临时授予对特定工具的访问权限 |
| **模型切换** | 从 Sonnet 切换到 Opus | 一些复杂任务需要更强的推理能力 |
| **上下文隔离** | 创建子会话空间 | 避免污染主会话的上下文 |

### 完全基于 LLM 推理的路由机制

这是一个非常重要的设计决策：**Claude 技能不使用硬编码路由**。

| 传统方法 | Claude 技能 |
|---------|--------------|
| ❌ 嵌入向量匹配 | ✅ 纯 LLM 推理 |
| ❌ 分类器 | ✅ Transformer 前向传播 |
| ❌ 正则或关键字匹配 | ✅ 自然语言理解 |
| ❌ 独立路由算法 | ✅ 统一模型决策 |

**工作流程**:

```text
1. The name and description of every Skill are formatted into the Skill tool description

2. Claude receives:
   - the user message
   - the list of available tools, including the Skill meta-tool
   - the Skill list, with name + description

3. Claude's natural language understanding matches the user's intent to a Skill description

4. When the match succeeds, it calls: command: "skill-name"
```

**为什么要这样设计？**

**硬编码路由需要**：
- 额外的维护成本
- 无法理解复杂的语义关系
- 难以处理多语言
- 不支持模糊匹配

**纯 LLM 推理**：
- 利用 Claude 自身的语言理解能力
- 自动处理多语言、同义词和模糊描述
- 不需要额外维护
- 使路由决策更智能

### 文件解析机制

**`SKILL.md` 文件结构**：

```bash
my-custom-skill/
├── SKILL.md              # Required: core definition file
├── config.json           # Optional: metadata config
├── README.md             # Recommended: usage documentation
├── scripts/              # Optional: executable scripts
├── templates/            # Optional: template folder
└── references/           # Optional: reference documents
```

**解析流程**:

```text
┌─────────────────────────────────────────────────────────────┐
│                    Claude Code startup                      │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Scan ~/.claude/skills/ and .claude/skills/ directories    │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Use the gray-matter library to parse each SKILL.md        │
│  YAML frontmatter                                           │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Validate required fields (name and description)           │
│  - name: max 64 characters, only lowercase letters,        │
│    numbers, and hyphens                                     │
│  - description: used for LLM automatic matching            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Extract metadata and build the Skill list                 │
│  (only load name + description, not the full body)         │
└─────────────────────────────────────────────────────────────┘
```

### 完整执行流程示例

让我们通过一个具体例子来看整个流程：

```text
User: "Help me analyze this PDF file"

═══════════════════════════════════════════════════════════════

Step 1: LLM decision
────────────────
Claude finds the description of the "pdf" skill in the Skill list:
  description: "Analyze PDF document content, extract text, generate a summary"

═══════════════════════════════════════════════════════════════

Step 2: System intervention
────────────────
Claude Code executes:
  1. Read ~/.claude/skills/pdf/SKILL.md
  2. Generate a visible message: "The pdf skill is loading"
  3. Generate a hidden meta-message: the full SKILL.md content
  4. Modify session permissions: allowed-tools = ["Bash(pdftotext:*)"]

═══════════════════════════════════════════════════════════════

Step 3: LLM execution
────────────────
Now Claude's context contains:
  - the original user request
  - the PDF expert workflow instructions
  - access permission to the pdftotext tool

Claude executes:
  1. Use pdftotext to extract the PDF text
  2. Analyze the content structure
  3. Generate a summary report
  4. Present the result to the user

═══════════════════════════════════════════════════════════════

Step 4: Dispose after use
────────────────
After the task is completed, the full Skill content is removed from context
(only the conversation history remains, not the full Skill instruction)
```

### 核心设计创新

| 创新 | 传统方法 | Skills 方法 | 优势 |
|--------|---------|------------|------|
| **能力来源** | 固定在模型权重中 | 动态加载提示 | 可扩展且可更新 |
| **令牌效率** | 所有能力始终驻留在内存中 | 按需加载 | 节省 80% 令牌 |
| **知识管理** | 分散在对话历史中 | 模块化文件系统 | 可版本控制且可共享 |
| **生命周期** | 持续占用空间 | 使用后即释放 | 上下文更干净 |

### 学术基础

Claude Skills 的设计借鉴了以下研究：

| 研究领域 | 代表性工作 | 在此应用为 |
|---------|---------|---------|
| **强化学习** | Voyager (2023) | 积累技能库的理念 |
| **认知架构** | ACT-R, Soar | 程序记忆与陈述性记忆的分离 |
| **分层策略** | Options 框架 | 三层渐进加载 |

**核心思维转变**:

```text
Traditional: AI needs to remember everything
      ↓
Skills: AI knows where to find specialized knowledge
      ↓
Result: more like the thinking pattern of a human expert
```

### 与 智能体 Skills 标准的关系

Claude Skills 遵循 [智能体 Skills 开放标准](https://agentskills.io/)，这意味着：

- ✅ 跨平台兼容性：例如 Cursor、Windsurf 和 Aider 等工具也支持它
- ✅ 统一文件格式：标准化的 `SKILL.md` 结构
- ✅ 互操作性：技能可以在不同工具之间共享

```text
Agent Skills standard defines:
├── Required: SKILL.md file (metadata + instructions)
├── Optional: scripts/ (executable code)
├── Optional: references/ (knowledge base documents)
└── Optional: assets/ (templates and resources)
```

### 总结：为什么这个设计很棒？

1. **将能力与模型解耦**：专业知识不再依赖模型训练，可以随时通过 Markdown 文件更新

2. **极高的令牌效率**：三层加载机制确保只加载必要内容

3. **利用 LLM 自身的优势**：路由和匹配完全依赖 Claude 的语言理解，无需额外算法

4. **开发者友好**：创建一个技能只需编写 Markdown，而不需要编程

5. **可组合**：技能可以相互引用和组合，形成复杂工作流程

6. **使用后自动清理**：完成后自动清理，保持上下文新鲜
