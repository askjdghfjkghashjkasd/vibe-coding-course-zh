# 如何构建带后端的微信小程序

上一章构建了一个小程序，其页面运行在用户手机上。本章增加了公司服务需要的部分：可信身份、共享记录、权限、文件和日志。

我们将把现有项目转变为**北极星服务中心**。会员打开迷你程序，创建售后工单，之后在其他设备上看到同一张工单。员工可以在公司系统处理，无需在迷你计划中放置公司机密。

![优步微信小程序中的路线、订单和付款界面](../../../../zh-cn/stage-3/cross-platform/wechat-miniprogram/images/wechat-uber-mini-program.png）

这就是许多公司迷你程序后端的角色：迷你程序是方便的入口;后端负责订单、会员、工单、权限和集成。

## 1.理解双方

**前端**是微信运行的内容：页面、按钮、表单和可见状态。**后端**运行在可信的云或公司环境中：身份检查、业务规则、数据库写入、文件存储以及调用内部系统。

用户可以更改前端发送的请求。因此，后端必须决定呼叫者是谁，以及调用者可以做什么。

对于第一个项目，使用最短的官方路径：

> 微信云开发→云功能→文档数据库和云存储

CloudBase托管和现有公司后端是后续的合理选择。PostgreSQL适合复杂的SQL关系和事务，但它增加了设置和迁移工作。我们不需要它来处理第一个工单工作流程。

## 3.创建一个云开发环境

在微信开发工具中开云开发，创建一个环境。控制台可能提供付费套餐;价格和免费配额会变化，因此请在继续前阅读当前购买页面。后端并非仅仅因为产品是迷你程序就必须——只有当用户需要共享账户、记录、文件、支付或公司数据时才需要。

如果 CloudBase 不适用，公司可以使用现有的 HTTPS 后端或其他托管后端。本章中的身份和权限规则仍然适用。

## 5.创建第一个云函数

**云函数**是CloudBase在Mini程序调用时运行的后端代码。从一个小函数开始，这样部署和日志就容易理解。

> 添加一个返回当前服务器时间的云函数。添加一个页面按钮来调用并显示结果。然后告诉我该在微信开发工具中具体部署该函数的位置。

部署函数，点击按钮，确认返回的时间变化。如果调用失败，先阅读 DevTools 错误和函数日志，再编辑更多代码。

## 6.让后端识别当前用户

前端不能说“我是这个用户”或“我是管理员”。在原生微信云路径中，云功能可以从微信的可信通话上下文读取来电者。

> 在工作云功能中添加“获取当前用户”。从微信的可信上下文中识别来电者，而非页面发送的ID或角色。仅显示页面所需的成员信息。

不要在接口中显示完整的OpenID，也不要在普通日志中写入完整的身份和联系方式数据。

## 7.保存第一张票

创建工单文档集合。第一个工单可以包含主题、描述、状态、创建时间和可信的所有者。

> 通过云函数保存工单表单。在服务器上检查必填字段，将受信任的当前用户添加为所有者，并返回可读取的工单编号。

部署后，提交一张工单。成功必须在两个地方可见：页面显示工单编号，数据库控制台包含一条匹配记录。

![完成的 Northstar 服务中心会员和工单界面](../../../../zh-cn/stage-3/cross-platform/wechat-miniprogram-backend/images/wechat-enterprise-service-hub.png)

![当前 CloudBase 文档数据库指南](../../../../zh-cn/stage-3/cross-platform/wechat-miniprogram-backend/images/cloudbase-database-guide-current.jpg)

由云函数或管理 API 写入的记录不会自动获得 `_openid`。如果所有权规则需要，函数必须基于受信任的上下文写入所有权，而不是前端选择的值。

## 8. 防止重复提交

一次页面点击测试只能证明按钮可能被禁用。网络重试仍可能创建第二张工单，除非后端识别相同请求。

> 给每次提交赋予一个稳定的 `clientRequestId`。如果再次发送相同 ID，则返回原始工单而不是创建另一张。

通过独立发送两次相同的 `clientRequestId` 来测试。两次调用都应返回相同的工单编号，数据库中应只有一条工单。新的 ID 应创建新的工单。

## 9. 仅显示当前用户的工单

> 通过云函数加载“我的工单”。仅返回由受信任当前用户拥有的工单。页面不能通过更改 ID 请求其他用户的工单。

使用两个微信账号测试。每个账号应只看到自己的数据。然后故意修改请求并确认后端拒绝。

数据库规则是第二层保护，特别是客户端直接读取集合时。对于初学者项目，通过云函数路由敏感写入通常使权限边界更容易审查。

## 10. 添加照片附件

普通工单功能正常前不要添加上传。

> 允许用户附加最多三张工单照片。限制类型和大小，显示上传进度，仅保存控制的云文件 ID 与工单关联。

使用临时下载链接或经过检查的后端访问，而不是让每个文件永久公开。在服务真实用户之前，添加文本和上传媒体的适当内容审核流程。

## 11. 失败时读取日志

常见问题包括错误的环境 ID、未部署函数、缺失集合、被拒的数据库规则以及从未写入的记录。

![当前 CloudBase 日志搜索指南](../../../../zh-cn/stage-3/cross-platform/wechat-miniprogram-backend/images/cloudbase-log-guide-current.jpg)

给 AI 精确证据：

> 页面显示此错误：【粘贴它】。云函数日志显示：【粘贴它】。找到第一个失败步骤，仅更改该部分。

修复后，重复同一操作，并保留页面结果和后端日志作为证据。

## 12. 分离开发和生产

学习阶段一个环境就足够。在真实用户到来之前，创建独立的开发、测试和生产环境，并在集中配置中保存其 ID。

在上传小程序之前，将云函数和安全规则部署到目标环境中。切勿在客户端中分发公司范围的 API 密钥。对现有内部系统的调用应通过公司控制的后端或网关进行。

现代 HTTP 云函数支持的不仅仅是短请求/响应调用，还包括当前的 WebSocket 和 SSE 场景。当项目确实需要完整框架、自定义运行时或容器时，可以考虑 CloudBase 托管。当关系、SQL 和更强的事务需求需要时，可以考虑 PostgreSQL。

## 13. 上传体验版

小程序的上传步骤与上一章保持一致，但后端需要进行自身的发布检查：

- 已选择生产环境；
- 云函数已部署；
- 集合和索引已存在；
- 访问规则已复核；
- 日志和告警可用；
- 审核账号和测试记录已准备；
- 在发布构建中重复两账号隔离。

## 14. 本章终点

当一个用户可以创建工单、看到工单号、找到匹配的数据库记录、在另一设备上重新打开小程序并仍看到相同工单，而第二个账号无法读取时，工作流程即完成。

上方 CloudBase 文档和控制台入口点的截图为真实参考，但并不意味着已代表读者创建了付费环境。定价、账号验证、生产环境规则及公司整合必须在将拥有该应用的账号中完成。

一旦这一小路径可靠，相同模式便可支持预约、维修请求、会员记录、内部审批及订单售后服务：页面收集意图，后端识别调用者，规则保护数据，日志显示发生了什么。
