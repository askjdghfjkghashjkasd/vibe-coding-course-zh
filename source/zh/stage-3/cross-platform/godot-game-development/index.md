# 如何用Godot构建平台、像素艺术和3D游戏

Godot 是一个免费的开源游戏引擎。它集成了场景编辑器、动画工具、物理物理、音频、输入、脚本和导出器，集成在一个应用程序中。它是强大的第一引擎，因为你可以检查每个场景和脚本，无需依赖专有服务。

本章使用了三个非常小的原型：一个2D平台跳跃游戏、一个像素艺术收藏循环和一个3D灰盒。目标不是假装一节课能做出三款成品游戏。而是理解每种项目的基本结构，并留下真正运行起来的东西。

## 1.记住你到处都能看到的四个词

- **node** 是一个具有一个任务的对象：精灵、摄像机、碰撞形状、标签、光源或声音。
- **scene** 是一个可重复使用的节点树。玩家、关卡和菜单都可以是一个场景。
- **脚本**赋予节点行为。
- **GDScript** 是 Godot 的主要脚本语言。它的语法对见过 Python 的人来说易于理解，尽管它是另一种语言。

Godot 也支持 C#。引擎扩展和性能关键系统可以使用 C，但初学者在下面的原型中不需要 C。

![Godot编辑器中的平台原型场景树和2D工作区](../../../../zh-cn/stage-3/跨平台/Godot-Game-development/images/godot-editor-platformer.png）

## 2.安装Godot并打开一个空白项目

从[godotengine.org]（https://godotengine.org/download/）下载当前稳定版本。在空文件夹中创建项目，使用前发渲染器用于现代桌面3D项目，或兼容模式以支持更广泛的硬件和网页。

在让AI制作游戏之前，先创建一个场景，保存它，然后点击运行。这样就能确认编辑器可以加载项目了。

## 3.路线一：一款小型2D平台游戏

### 一个已发布的例子：原始之光

《原始之光》是一款商业2D动作平台游戏，收录于Godot的展示中。其截图使路线清晰可辨：平台形成清晰的轮廓，危险与背景形成对比，玩家还能看到下一步该去哪里。

![《原始之光》官方Godot展演](../../../../zh-cn/stage-3/cross-platform/godot-game-development/images/godot-case-primal-light.webp）

参考文献：[Godot展演中的原始之光]（https://godotengine.org/showcase/primal-light/ 年）。

我们的原型**Skyline Courier**只借鉴了这些结构理念：可见的路线、简洁的平台和明亮的目的地。

请问你的编码助理：

>创建一个2D平台关卡，包含一名玩家、一个地板、三个平台和一个可见的目标。目前先用简单的形状。

在添加插图之前先运行它。

>增加左右移动以及跳跃。玩家必须站在平台上，且不得在空中再次跳跃。

![Skyline Courier 在 Godot 4.7.1 中运行](../../../../zh-cn/stage-3/跨平台/Godot-Game-development/images/godot-run-platformer.png）

试着走到平台边缘，从每个平台跳下去，然后从关卡上掉下来。然后添加一条重启规则：

> 如果玩家跌到关卡以下，则将其送回起点。

继续阅读Godot的[首个2D游戏教程]（https://docs.godotengine.org/en/stable/getting_started/first_2d_game/index.html）。

## 4.路线二：像素艺术收集循环

### 一个已发布的例子：穹顶守护者

《Dome Keeper》结合了可读的像素艺术表面、采矿、资源和升级。有用的参考不是“复制这款游戏”。而是小屏幕如何保持资源数量和明确目标。

![官方Godot展示中的圆顶守护者](../../../../zh-cn/stage-3/跨平台/godot-game-development/images/godot-case-dome-keeper.webp）

参考资料：[Godot展示中的圆顶守护者]（https://godotengine.org/showcase/dome-keeper/ 年）。

我们的原型是**灯笼森林**：穿过一个屏幕收集发光物体。

>创建一个320×180像素艺术场景，包含一名玩家、一片森林空地、三个收藏品和一个计数器。保持艺术作品为简单的彩色精灵。

> 当玩家触摸收藏品时，取下它并增加计数器一次。

![《绿灯林》在Godot 4.7.1中运行](../../../../zh-cn/stage-3/跨平台/godot-game-development/images/godot-run-pixel.png）

当精灵落在显示像素之间或视口缩放不均时，像素艺术会变得模糊。配置整数缩放，并测试窗口和全屏模式。

阅读Godot的[多分辨率指南]（https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html）和[TileMap指南]（https://docs.godotengine.org/en/stable/tutorials/2d/using_tilemaps.html）。

## 5.第三条路线：一个3D灰盒

### 一个已发布的例子：锻造之肉

《锻造之肉》是一款用Godot制作的第一人称游戏。其官方展示图片是空间剪影、光影和强烈视觉目标的有用参考。

![《锻造之肉》官方戈多展示会](../../../../zh-cn/stage-3/跨平台/godot-game-development/images/godot-case-wrought-flesh.webp）

参考资料：[Godot展演中的锻造肉体]（https://godotengine.org/showcase/wrought-flesh/ 年）。

灰盒**是在最终模型到来之前，由箱子、飞机和简单材料搭建的关卡。它让团队可以低成本测试规模、移动、视线和目标。

我们的灰盒是**信号花园**。

>创建一个小型3D灰盒，里面有地板、墙壁、可控制的玩家、摄像机和发光的出口。只使用原始网格。

> 添加定向光、柔和环境光和阴影，确保路线清晰可辨。

![Godot 4.7.1 中运行的信号花园](../../../../zh-cn/stage-3/跨平台/Godot-Game-development/images/godot-run-3d.png）

走进每一面墙，上下看看，确认玩家不会从地板中掉落。然后继续玩Godot的[第一个3D游戏教程]（https://docs.godotengine.org/en/stable/getting_started/first_3d_game/index.html）。

## 6.保持AI改动小

当一个提示同时更改移动、关卡美术、敌人、界面、保存和导出时，游戏项目就变得难以调试。一个有用的序列是：

> 只添加玩家移动。不要更改关卡。

> 跳跃感觉太高了。只降低跳跃高度，然后给我看看你改的数值。

> 添加一个收藏品和一个计数器。暂时不要添加敌人。

当出现故障时，提供准确的错误和脚本的节点：

> 项目以以下错误结束：【粘贴错误】。只修复这个错误并说明我如何验证它。

## 7.游戏循环成功后添加资源

一次替换一个占位符。记录素材源和授权。每次更换后确认精灵缩放、枢轴、碰撞、动画和导入设置。

对于3D资源，请单独检查物理尺寸和碰撞。一个漂亮的模型并不意味着自动就有可用的碰撞形状。

音频也同样需要注意：保持音乐和效果音在不同的总线上，并在发布前提供音量控制。

## 8. 导出是一个独立的步骤

在编辑器中运行只证明了开发版本。打开 **编辑器 → 管理导出模板** 并安装与 Godot 版本完全匹配的模板。然后使用 **项目 → 导出** 为目标平台添加预设。

> 为当前目标配置导出预设。不要更改游戏内容。

如果导出失败：

> 导出失败，错误信息为：【粘贴错误】。仅检查模板和导出预设。

桌面构建需要在没有 Godot 编辑器的干净机器上测试。Web 构建必须通过本地服务器或 HTTPS 提供，而不能通过双击 HTML 文件打开。安卓和 iOS 还需要它们的 SDK、签名、权限和设备测试。

## 9. 下一步去哪里

选择最接近你想要的游戏的原型：

- 扩展带有一个敌人和一个检查点的平台游戏；
- 扩展带有更大 TileMap 和小资源循环的像素原型；
- 扩展带有一次交互和更明确目标的3D灰盒。

本章的三个原型是在 macOS 上的 Godot 4.7.1 中加载和运行的。它们的场景加载、基础移动、碰撞、计数器和光照都在上面展示的临时测试项目中进行了验证。

Windows、Linux、Web、Android、iOS 和主机平台的导出不能算作完整。每个平台都需要匹配的模板、SDK、签名和目标硬件。

当一个小循环值得重复时，游戏才开始有真实感。选择一条路径，使五分钟的玩法可靠，然后再添加更多关卡、艺术和系统。
