# 如何学习这门课程

::: 信息 特别感谢
本课程的核心贡献者和测试者来自**清华大学深圳国际研究生院**。感谢那些不断发现问题、提出建议并通过真实学习和实践帮助复习材料的学生们。他们的工作使课程更加清晰、可靠，也更贴近初学者真正需要的内容。[** 👉 查看完整贡献者名单**]（https://github.com/datawhalechina/easy-vibe#-contributing--contributors）
:::

过去，开发软件门槛很高。你必须学习编程语言、开发工具和大量技术知识，才能让一个想法成为可运行的程序。大型语言模型和人工智能编码工具改变了这一点：人们现在可以用自然语言描述意图，并让人工智能生成代码、构建界面和修改功能。

## 从氛围编码到建筑产品

**术语[氛围编程]（https://www.merriam-webster.com/dictionary/vibe coding）于2025年2月2日出现。** 人工智能研究员Andrej Karpathy用它来描述一种新的编程方式：人们主要用自然语言告诉AI他们想要什么，观察结果，然后继续对话，而不是从头写、理解和管理每一行。

> **什么是Vibe编码？**
> 简单来说，这就是“通过对话编程”：描述一个想法，让AI生成程序，运行它，并通过对话不断调整。

它的第一个突破是让更多人跨越“我不会编程，所以不能开始”的障碍。现在，没有编程经验的人可以在几分钟内创建一个小型游戏、网页或可演示的原型。

这是一个重大变化：**人们与计算机交流的方式正从严格的编程语法扩展到自然语言。**

但随着工作演示变得更容易制作，新的问题也随之而来：

- 我们应该建造什么，而不仅仅是能建造什么？
- 它解决了谁的问题？那些人真的需要它吗？
- AI生成的第一版如何变得稳定、易懂且可维护？
- 我们如何交付产品，而不是只在自己的电脑上运行？
- 使用、反馈和支付如何证明它创造了真正的价值？

氛围编码并不能消除学习的需求。它**改变并提高了要求**。

如果只看编码，目标就是让代码运行起来。构建产品意味着对从问题到结果的整个过程负责：

> **编程：我能做到吗？**<br>
> **构建产品：值得制作吗？谁会使用它？我将如何交付它？我如何确定它有效？**

Vibe编码是本课程的起点，而非终点。我们将先快速制作，然后学习如何选择问题、验证需求、设计解决方案、构建产品、与用户会面，并从结果中迭代。

::: 提示 这门课程到底发展了什么？
这门课程不仅仅是关于使用AI编码工具。它的目标是帮助你成为一名入门级的**产品工程师**：能够发现问题、验证需求、构建产品、交付给真实用户，并从成果中持续改进。
:::

## 为什么现在需要产品工程师？

产品工程并非2026年突然出现。

早在2018年，Intercom就用产品工程师来描述拥有产品所有权的工程师：不仅仅实现他人已设计的功能，还了解客户、参与产品决策并不断改进产品交付。

人工智能大幅降低了“制造成功”的成本，使工程师能够在多个角色分工后承担工作。借助大型模型和编码代理，一个人可以更轻松地跨越原型、接口、前后端、人工智能集成、测试和部署。因此，工作不仅仅是“完成代码”：直接了解用户，验证解决方案，鼓励采用，并对业务成果负责。

### 这些变化意味着什么？

这种转变不仅仅是公司要求工程师做更多事情。它改变了已经写代码的人的角色，同时也为那些没有写代码的人创造了新的入门途径。

#### 对于已经写代码的人来说：工程师角色正在被重新定义

- **起点发生变化：**不再等待书面的需求，而是进入用户和业务场景中发现问题。
- **原型的目的发生变化：**它不仅仅是技术演示；它迅速触达用户并验证判断。
- **工程边界发生变化：**从单一技术模块扩展到界面、后端、人工智能、部署和用户体验。
- **成功衡量标准发生变化：**从“功能发布”转向采用率、节省时间、转化率、收入以及实际影响。
- **与销售的关系发生变化：**一些产品工程师参与演示、概念验证和客户上线，通过技术证明价值。

“知道如何销售”并不意味着每个人都必须成为传统销售人员。对于产品工程师来说，它首先意味着能够找到可能需要产品的人，理解他们的问题，展示解决方案，邀请他们使用，并了解他们是否会继续使用或付费。

#### 对不写代码的初学者：一个新门已经打开

人工智能不仅正在改变工程工作，它还降低了构建产品的门槛。

过去，一个不会编程的人可能只能制作思维导图、原型或幻灯片，但要构建一个可运行的产品仍需找工程师或花费多年学习编程。现在，这不再是唯一的途径：

- **你无需在开始前学习多年编程。**你可以用自然语言描述需求，让 AI 生成代码和界面，并在构建可运行产品的过程中处理错误。
- **领域知识可能比编码能力更稀缺。**教师、医生、律师、销售人员、运营者以及有经验的行业从业者了解真实用户和工作流程。这些知识往往是技术团队所缺乏的，也是构建有价值产品的关键。
- **从“我有一个想法”到“我做出一个产品”的距离可以缩短到几周甚至几天。**你可以把一个熟悉的行业问题转化为一个小工具，交给真实用户，并测试它是否创造价值。

本课程面向两类群体：想扩展职责范围的工程师，以及拥有想法或领域知识的初学者。两者都可以从这里开始，学习将想法转化为解决真实问题的产品。

### 产品工程师、FDE 和 OPC 之间的关系

这些概念位于同一能力链上，但它们不是同一事物。

| 概念 | 定义 | 主要场景 | 职责范围 |
| --- | --- | --- | --- |
| **产品工程师** | 兼具产品和工程角色 | 产品团队内部 | 从问题和解决方案到发布、用户反馈和业务指标 |
| **FDE（前端部署工程师）** | 产品工程延伸到客户场景 | 企业客户、真实运营和生产环境 | 发现、概念验证、集成、部署、采用、扩展，有时包括销售周期 |
| **OPC（单人公司）** | 由一个核心个人运营的公司，而非职位 | 一个人利用 AI 代理、自动化平台和外部服务运营产品 | 市场发现、产品、营销、销售、交付、支持和现金流 |

<p class="role-path-caption">这不是每个人都必须按顺序爬升的职业阶梯，而是展示了相同产品工程能力可以覆盖的不同范围。</p>

把它们想象成三个不断扩展的圆圈：

> **产品工程师：构建正确的产品并使其可工作**<br>
> **FDE：将产品引入客户环境并创造结果**<br>
> **OPC：使用相同能力运营完整的业务**

#### FDE：工程师进入客户环境

FDE既不是只安装软件的实施专家，也不是只做演示的售前工程师。在AI公司中，FDE通常做四件事：

1. 与客户一起找到最有价值的问题。
2. 快速构建原型或概念验证，以展示技术和业务价值。
3. 编写生产代码，并将解决方案连接到真实的客户数据和工作流程。
4. 观察采用情况，将重复需求转化为通用产品能力。

截至2026年8月，OpenAI正在多个国家和城市招募FDE，并将成功定义为生产采用情况、可衡量的工作流程影响以及可以改变产品和模型路线图的现场反馈。FDE正在从一些企业软件公司的特殊实践发展为交付AI的重要方式。

#### OPC：一个人可以拥有“数字团队”

这里的OPC不仅指法律上的单人公司。它指的是**单人公司：由一个人领导，通过使用软件、AI代理和外部基础设施来完成曾经需要更大团队工作的业务**。

这不是完全由AI操作的“无人公司”。创始人仍必须判断市场、承担责任、接触用户并做出关键决策。AI更像是一个可以分配任务的数字团队。

这一趋势并非从AI开始。独立开发者Pieter Levels在他的网站上解释说，他长期以来自己构建和运营Nomads.com、Remote OK、Photo AI、Interior AI等产品。AI可以将该模式扩展到设计、编程、内容、分析和支持，但真实市场仍决定产品是否有价值。[参见Pieter Levels的项目记录](https://levels.io/projects/)

在2025年，微软《工作趋势指数》使用**智能体 Boss**指代那些创建、委派并管理AI代理的员工。该报告调查了31个国家的31,000名员工，81%的领导者预计代理将在12–18个月内中度或广泛地整合到他们的AI战略中。[参见微软2025年工作趋势指数](https://www.microsoft.com/en-us/worklab/work-trend-index/2025-the-year-the-frontier-firm-is-born)

2025年6月，Wix以约8000万美元收购了自然语言应用开发平台Base44。Base44不严格算是OPC，但它展示了一个重要的使能条件：数据库、身份验证和部署——曾经需要多个角色完成的工作——正在通过会话产品被打包和自动化。[参见Wix的收购公告](https://www.wix.com/press-room/home/post/wix-further-expands-into-vibe-coding-with-acquisition-of-base44-a-hyper-growth-startup-that-simplif)

关于第一个一人独角兽何时出现的问题仍然是预测，而非已实现的事实。对初学者更有用的现实是：**一个人已经可以用更少的资金和更小的团队更快地验证一个产品，并可以经营一个适度但真正盈利的业务。**

::: tip 为什么课程讨论这三条路径？
无论你以后是加入产品团队、成为FDE，还是尝试OPC，起点都是同一套产品工程基础：找到真正的问题，构建最小化产品，将其交付给用户，解释其价值，并根据使用和支付进行迭代。
:::

因此，课程训练的是一个完整的产品循环，而不是多个分散的职位：

> **发现问题 → 验证需求 → 设计解决方案 → 构建产品 → 交付用户 → 解释价值 → 观察结果 → 持续迭代**

当然，让AI编写代码只是第一步。一个可用的产品会提出更多问题：

- 如何让AI写出干净、可维护的代码？
- 如何将分散的代码组装成一个可运行的应用？
- 如何将应用上线让其他人使用？
- 如何添加AI功能，如文本生成和图像理解？
- 如何知道用户是否需要它，甚至可能为此支付？

你将在整个课程中找到这些问题的答案。

无论你是学生、教师、医生、工人，还是完全不懂技术的人，你都无需多年学习编程，就能开始你的第一个产品原型。

| 你的角色 | 本课程如何帮助 |
| --- | --- |
| 学生 | 独立完成作业、竞赛和创业项目 |
| 专业人士 | 自动化重复工作，提高效率，创建副业 |
| 产品经理 / 设计师 | 将想法变为演示并展示给用户 |
| 企业家 / 小企业主 | 以低成本验证想法，在组建完整团队前制作MVP |
| 教师 / 教育工作者 | 创建教学工具、课件和自动化练习 |
| 医生 / 律师 / 专业人士 | 自动化专业工作流程并构建个人生产力工具 |
| 任何人 | 利用AI解决生活或工作中的具体问题 |

AI降低了实现成本，但产品价值仍取决于你是否找到真正的问题并将解决方案交付给用户。

# 课程结束后你能做什么？

## 第一阶段：打造你的第一个产品原型

这个阶段适合完全初学者，以及那些懂一点代码但还没有信心的人。你不会先学习大量理论。你学会让AI写代码并在构建过程中修正错误。

**在这个阶段之后你可以：**

- 独立完成使用AI编码工具的网页应用;
- 将产品创意转化为可点击、互动的原型;
- 添加人工智能功能，如图像生成和智能对话;
- 调查并解决错误，而不是在第一次故障时停下脚步。

简而言之，你可以做出一个运行起来、可以向别人演示的东西。

我们从一个小游戏开始，然后学习使用AI编码工具编写代码和处理错误。从一个简单的页面开始，我们构建一个互动式多页应用，添加AI功能，完成一个独立项目，让一个想法真正有机会传播到世界。

# 为什么要通过项目来训练？

> **真正工作的挑战**
>
> 在真实职场中，你通常会得到一个目标，但没有完整的文档、现成的框架或详细的要求。

> 你的主管或客户：我们需要建立xxx并实现yyy。
>
>文档？现有框架？详细规范？通常这些都不存在。

许多真正的工作意味着在不确定性下解决一个陌生的问题。需求模糊，界限不断变化，没有人给出标准答案。你必须研究、实验、原型、迭代，最终交付一个运行、可运行且可发布的解决方案。

课程为你提供了一个安全的模拟体验：

- 具有挑战性的项目迫使你拆解问题、设计解决方案并寻找信息;
- 不过度简化的脚手架帮助你学习阅读、理解和修改中等规模代码库;
- 从构想到发布的整个过程，让你体验从零到零的真实产品旅程。

这种培训短期内可能感觉困难，但它增强了你承担责任的能力，找到克服不确定性的方法，并将人工智能变成真正的产品而非演示。

# 提问的艺术：人工智能时代的基本技能

提问是一项核心技能。用同样的代码和错误，**你怎么问往往决定你得到的答案**：模糊的讨论或可执行的顺序。

**养成习惯：**把提问AI当作开发的一部分。当你不理解或卡住时，立刻提问。

## 为什么这是一项必备技能？

- **实际工作很少有完整的文档：** 要求可能不明确，代码未完成，错误零散。
- **AI可以是导师和同事：**好的问题能让它变成高质量的配对编程。
- **沟通设定上限：** 你提供的越相关的上下文和输出约束，答案就越有用。

**常见错误：** “为什么会有错误？”通常会产生猜测。包含上下文以获得可执行计划。

## 如何向人工智能提供信息：截图还是复制粘贴？

两种方法都有效，但适用于不同的情况：

|方法 |适用于 |关键要求 |
|--- |--- |--- |
|**复制粘贴** |错误堆栈、日志、代码、配置、API响应 |包含完整相关文本，而非单一关键词 |
|**截图** |布局问题、交互问题，或工具中缺少按钮 |捕捉足够的上下文，标记重要区域，并添加一句话 |

::: 危险 ⚠️ 重要状况
**并非所有AI都接受图像输入。**基于截图的通信需要能够理解图像的多模态模型。例如Claude、GPT-4V/GPT-4o、Gemini，以及一些中国模型如Qwen和ERNIE Bot。

**如果你的AI不接受图片**，它就无法读取截图。改为复制粘贴文本。
:::

## 帮助AI良好解释的提示

如果你想了解答案，而不仅仅是接受答案，像这样的说明可以更好地说明：

> **以学习为导向的示例**
>
> - “用五句话解释这个概念，然后问我几个问题来检查我的理解。”
> - “详细解释这个错误。我不明白为什么会发生。”

# 我努力了很久，想放弃

也许需要改变的是方法，而不是你的坚持。不要独自挣扎。与作者和助教交流，描述你尝试过什么、卡住的地方以及你的感受。方向上的一点小改变或一个缺失的概念，往往能帮助你继续前进。

# 赛道设计的某些部分感觉不合理

请联系作者，发起问题，或在课堂或社区中提供反馈。告诉我们哪些不清楚、哪些地方不够好，以及哪些时间浪费了。诚实且具体的反馈有助于后续学习者避免同样的问题。
