# 完整项目实践：从一个想法到完成的作品


## 这一章的意义

<章节引言 :d uration=“duration” ：tags=“['完全使用'，'产品体验'，'用户试用'，'项目演示']” coreOutput=“一个别人可以无指导使用”expectedOutput=“通过真实用户试用改进的网页项目”>

在之前的章节中，我们从一个想法出发，构建了一个互动原型，并让页面上的AI功能正常运行。

你已经知道该输入什么，也知道该点击哪里。第一次打开页面的人甚至可能找不到第一步。如果点击后立刻没有任何信息出现，他们可能会认为页面坏了。

本章不会新增功能。我们将从头到尾使用产品，修正人们可能卡住的地方，然后请别人尝试。最终成果将是一个你可以自信分享的项目。

## 1.从头到尾使用你的产品

不要急于添加登录、团队协作或分析功能。按原样打开产品，像用户一样使用，从第一页开始直到得到结果。任何仍然需要你解释的步骤都需要改进。

对于我们的电商内容工作空间，一个完整的使用方式如下：

> 电商运营商上传产品图片，添加必要信息，生成第一份文本和图片草稿，检查后复制或保存以便编辑和发布。

让这段短暂的旅程顺利进行就足够了。登录、团队权限和正式发布可以等到产品真正需要时再做。

### 1.1 遵循真实使用顺序

暂时忽略代码和组件。按照用户会采取的操作：

1. 打开页面，了解该工具能帮助什么。
2. 上传产品图片，填写必要信息，如名称和材料。
3. 选择“生成副本”，查看页面正在处理请求。
4. 检查AI返回的标题和卖点;必要时编辑或重新生成。
5. 复制、下载或临时保存结果并完成任务。

当你完成后，问自己：如果我不站在他们旁边，别人会被卡住吗？记录诸如团队管理和复杂仪表板等功能，但如果它们不影响此使用场景，现在不要构建它们。

::: 提示 这个版本应该多大？
如果你可以用一句话告诉别人任务，并且他们可以在几分钟内开始，那么范围通常是合适的。
:::

### 1.2 从空白页面再次尝试

在产品上工作一段时间后，页面通常会包含测试数据和旧结果。很容易忘记初次使用者看不到这些内容。打开一个隐私窗口或清除本地数据，然后重新开始。

你只需要尝试三种情况：

1. **打开空白页面：** 不输入任何内容就点击，查看页面是否解释了缺少的内容。
2. **正常生成：** 上传一张图片并生成内容；确认等待状态可见，结果有明确的下一步。
3. **引发一次失败：** 上传不支持的文件或使请求失败；确认输入的内容仍保留，并且用户可以再次尝试。

写下你卡住的地方。我们将在下一部分修复这些地方。

AI 集成开发环境 可以检查代码，但它不能替代实际使用页面：

```text
Do not change the code yet.

Inspect the current project around this user task:
the user uploads a product image, enters the required information,
generates copy, checks the result, and then copies or saves it.

Tell me which pages and files this journey uses,
and list the places where it may currently stop.
```

AI集成开发环境可以指出可疑代码。你仍然需要点击页面才能判断是否可用。

## 2.修复用户通常卡住的地方

完成一次运行后，问题通常在四个时刻出现：首次打开、等待 AI、收到结果以及处理失败请求。你不需要复杂的设计。用户只需知道发生了什么以及接下来可以做什么。

### 2.1 第一步清楚吗？

空白页面不应仅包含输入字段。在上传区域附近添加一个简短说明、示例内容或关于支持图片格式和尺寸的说明。

如果表单有多个字段，只保留产生有用结果所需的字段。产品名称、图片和主要特征可能需要填写;品牌、参考链接和详细风格设置可以放在“更多设置”下。新用户在尝试产品前不应需要填写冗长的注册表。

### 2.2 页面点击后会响应吗？

AI请求可能需要几秒钟甚至更久。点击后，按钮应显示“正在生成”，并暂时阻止重复提交。现有输入不应突然消失，页面也不应跳转到空的结果面板。

![产品内容生成时等待状态](../../../zh-cn/stage-1/building-prototype/images/index-2026-01-14-15-50-05.webp）

*等待状态不需要复杂的动画。显示工作已开始，同时保留原始输入和位置，已经能避免大多数混淆。*

对于排队的图像或视频工作，你可以显示“排队中”和“生成”阶段。除非API实际提供进度，否则不要虚构精确百分比。

### 2.3 结果出现后会发生什么？

AI输出并非终点。用户通常需要核实事实、修改措辞，并将结果带入下一阶段。因此，结果面板应至少提供一项有用的操作：编辑、复制、下载或重生成。

![图像理解与文案生成相关的结果页](../../../zh-cn/stage-1/integrating-ai-capabilities/images/index-2026-01-20-15-35-41.webp）

*本页面将上传的产品图片保持在识别和生成结果之上。用户可以将文本与原始图片进行比较，而无需接受一个模型答案。*

如果模型无法确认某些信息，标记该信息，让用户添加或删除。这比用一段文字作为最终答案更有用。

### 2.4 用户在失败后还能继续吗？

网络中断、配额用尽以及不支持的文件都可能导致请求失败。普通用户不需要完整的技术错误，但页面应说明该尝试未完成，并提供重试或编辑输入的方式。

例如：

- **不支持的图片格式：** 列出支持的格式并允许选择其他文件。
- **缺少所需信息：** 在相关字段旁显示消息，而不仅仅是显示“参数无效”。
- **AI服务暂时不可用：** 保留输入并提供“再次生成”。
- **结果不合适：** 允许用户修改输入并重试，无需重新开始。

如果刷新页面会导致长表丢失，可以使用LocalStorage保留临时草稿。只存储恢复任务所需的普通数据;绝不要将API密钥、真实客户信息或敏感文件存储在浏览器存储中。

将你发现的问题集中在一次请求中提交给 AI 集成开发环境：

```text
Check the “upload a product image and generate copy” journey
at four moments: start, waiting, success, and failure.

Fix the problems that prevent the user from continuing first:
- required fields have no clear message;
- the request button can be clicked repeatedly;
- a failed request clears the input;
- the result has no edit, copy, or regenerate action.

Before editing, tell me which files you will change.
When finished, give me manual test steps.
```

## 3. 请其他人使用它

在长时间查看自己的页面后，每个操作都显得理所当然。没有参与构建的人可以在几分钟内发现被忽略的问题。

尽可能邀请潜在用户。电子商务内容工具可以让有开店经验或准备过产品列表的人测试。如果那个人不可用，一个从未见过该页面的朋友也很有用。

### 3.1 只告诉他们任务

开始时，仅解释目标：

> 使用此工具从该产品图片生成标题和卖点。检查内容，然后复制你会继续编辑的版本。

在告诉他们点击位置前先观察。记录暂停、回退、重复点击和问题。如果立即解释，你会掩盖页面本应解决的问题。

即使只有一两个人，也可以揭示明显的问题。你不需要正式报告；只需记下他们停止的地方。

如果他们打开页面后什么也没做，增加简短的说明。如果他们反复点击“生成”，使等待状态更清楚。如果他们不知道如何处理结果，增加编辑或复制操作。如果失败迫使他们重新输入所有内容，保留内容并增加重试选项。

### 3.2 完成后再交流

当用户完成或放弃任务后，提问：

1. 哪一步让你最不确定？
2. 生成结果的哪些部分会直接使用，哪些你总是会更改？
3. 如果下次有相同任务，你会再次使用它吗？为什么？

不要只问“使用起来容易吗？”一个礼貌的“还行”几乎没有指导意义。具体的行为和实例更有价值。

::: warning 使用真实材料时
测试人员的产品图片、录音或文档可能包含真实的商业信息。说明哪种 AI 服务会接收材料，避免未经批准的客户数据，并在试用后删除不再需要的文件。
:::

## 4. 修复阻碍用户的问题，然后再次尝试

试用可能产生一长串问题。不要一次修复所有问题。从妨碍完成或使结果不可信的问题开始。

按以下顺序：

1. **任务无法完成：** 按钮损坏，请求失败，或结果无法获取。
2. **结果明显不可信：** 事实被编造，证据缺失，或必要来源无法验证。
3. **交互容易误解：** 起点或当前状态不清楚。
4. **操作耗费过高：** 步骤重复，输入消失，或等待无反馈。
5. **风格和新功能：** 视觉美化和不阻碍核心任务的需求。

选择最重要的一至三项。修复后，自己尝试完整流程。如果可能，邀请同一个人再次尝试。只有当原有阻碍确实消失时，修改才有用。

### 4.1 给 AI 集成开发环境 具体观察

不要只说“请优化它”。包括你观察到的内容，以便 AI 集成开发环境 知道需要更改什么：

```text
User task: upload a product image and generate three selling points.

Observed problem:
Two testers clicked “Generate” repeatedly because the page did not
clearly show that the request had started. This created duplicate jobs.

Change the current page:
1. Disable the button after the request starts and show “Generating.”
2. Restore it after success or failure.
3. Keep the information the user already entered.
4. Tell me how to test repeated clicks and a failed request manually.
```

一个如此具体的请求不太可能产生无关的更改，而且它会明确告诉你之后需要验证的内容。

### 4.2 再次运行完整流程

修复一部分可能会影响另一部分。在分享项目之前，尝试以下四种情况：

- 一个包含所有必填信息的正常输入；
- 缺少一个必填字段；
- API 请求失败或超时；
- 在收到结果后进行编辑、复制或重新生成。

如果产品保存草稿，也刷新页面一次。确认新行为可行，并且原始核心流程仍然有效。

## 5. 准备工作以便分享

项目现在不仅仅是“在你的电脑上运行”。另一个人已经使用过它，你也根据实际问题进行了改进。准备好入口点和说明，使更多人可以理解它。

### 5.1 用一分钟解释

按以下顺序：

1. **谁遇到了什么问题**：例如，电子商务运营人员在准备首个上架草稿时反复整理图片和卖点。
2. **产品如何帮助**：上传产品图片和信息即可获得可编辑的首个草稿。
3. **使用了哪些 AI 能力**：图像理解和文本生成。
4. **用户如何完成任务**：上传、生成、检查、编辑和复制。
5. **试用后的变化**：例如，可见的等待状态和失败后保留的输入。

在列出框架和模型名称之前，先帮助人们理解产品。这样结果更容易理解。

### 5.2 准备另一人需要的内容

在分享之前，准备三件事：

1. **可运行的应用程序**：提供链接；如果尚未部署，说明启动命令和本地地址。
2. **30–60 秒演示**：展示从输入到结果的核心任务，而不是快速切换页面。
3. **一页项目说明**：包括目标用户、核心问题、主要流程、AI 能力、一条用户反馈，以及由此产生的变化。

如果远程访问尚不可行，本地运行和演示视频可以作为第一阶段的证据。重点是另一个人可以理解工作并看到完整的核心流程。

### 5.3 继续这个项目还是开始新的项目？

你可以继续本章使用的电子商务内容工作空间，或者将相同流程应用于会议记录、音频内容、学习辅助或行业工具。[AI 应用场景指南](../appendix-industry-scenarios/index.md) 可以帮助你探索方向。

不要仅为了显得原创而开始不熟悉的主题。自己学习、工作或生活中的小问题，在真实用户尝试解决方案后，比起一页有许多没人使用的功能，更具说服力。

### 发送前

最后一次打开共享链接并完成整个流程。确认其他人可以打开，AI 返回结果，并且页面或截图上没有 API 密钥。如果使用了他人的图片、音频或文档，请确认你有使用权限。

## 下一步

你现在已经完成了一条完整路径：从一个真实问题开始，缩小第一个版本，构建交互式原型，连接AI，然后让用户尝试产品并改进它。

在阶段2中，我们将添加数据库、用户账户、支付、部署，以及更完善的前端和后端工程。这些功能让产品可以服务更多用户和真实数据，但起点仍然是你在此学到的：先完成一次有价值的用户任务。
